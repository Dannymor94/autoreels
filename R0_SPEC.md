# R0 — Выбор моментов: детальная спецификация

Ядро Авто-Рилс и единственное место реального риска. Облачный этап: транскрипт → кандидаты-клипы с заголовками. Всё остальное — детерминированная инженерия вокруг этого.

Принцип, который держит всю стадию: **LLM предлагает и ранжирует, код решает и валидирует.** Скоры и границы от модели — черновик; финал ставит детерминированный слой.

---

## 0. Поток данных R0

```
аудио (ffmpeg -vn)
  → транскрипция (Whisper, word-level)
    → нормализация в sentence-level + таймкоды        [код]
      → сжатие транскрипта под бюджет токенов          [код]
        → чанкинг (если длинный)                       [код]
          → LLM-вызов на каждый чанк                   [LLM]
            → парсинг + валидация кандидатов           [код]
              → дедуп пересечений между чанками        [код]
                → snap границ к словам/паузам          [код]
                  → ранжирование, отбор топ-N          [код]
                    → манифест (awaiting_review)
```

LLM трогается ровно в одной точке. Всё до и после — детерминированный код.

> **С M1.6** перед LLM стоит детерминированный предотбор (блоки → отсев → эвристика → top-K), и точку отбора может занять человек (`arl blocks --review/--apply`, §11). Эта спецификация описывает автоматический путь; ручной путь дальше по конвейеру неотличим от него, кроме поля `selection_source` и правила «ручной выбор не пересматривается» (`CLAUDE.md`, инвариант 5).

## 1. Вход в LLM: сжатый формат транскрипта

Word-level нужен **коду** (для snap границ при нарезке), но **не LLM** — модели хватает предложений с таймкодами. Отправка word-level в LLM сожгла бы бюджет токенов впустую.

Формат, который уходит в модель (одна строка = одно предложение):

```
[0124.3-0131.0] Самый важный момент в работе с травмой — это не сама травма.
[0131.0-0138.4] За ней всегда скрыт ресурс, который человек не замечает.
[0138.4-0145.1] И вот тут начинается самое интересное.
```

Правила сжатия (код, до отправки):
- предложения склеиваются из word-таймкодов по границам пауз/пунктуации;
- таймкоды — только начало-конец предложения, не каждое слово;
- филлеры-страховки («эээ», «ну вот», повторы) схлопываются;
- числовой индекс предложения **не нужен** — модель адресует сегменты таймкодами, и это же ключ для обратной привязки к word-level на этапе нарезки.

Экономия: ~2× против сырого word-level JSON — существенно для укладки в бюджет R0-чанка.

## 2. Рамка виральности (рубрика скоринга)

Модель оценивает каждый потенциальный сегмент по сигналам. Рубрика идёт в **system-промпт**:

**Сильные сигналы (повышают score):**
- **Hook в первых 3 сек** — сегмент открывается зацепкой, а не разгоном. Без хука клип мёртв.
- **Самодостаточность** — понятно без контекста остального видео.
- **Эмоциональный пик** — удивление, конфликт, инсайт, переворот ожидания.
- **Цитируемость** — есть фраза, которую хочется пересказать.
- **Вопрос → ответ** — закрытая микро-арка внутри клипа.
- **Контринтуитивность** — «на самом деле всё наоборот».

**Анти-сигналы (понижают / отбраковывают):**
- обрыв на полуслове, ссылка на «как я говорил раньше», незаконченная мысль;
- организационное («сделаем перерыв», «включите звук»);
- длинный разгон без пуанта.

**Калибровка score (0–100):** ≥80 — публиковать смело; 60–79 — годится; <60 — слабо, в норме не берём. Порог отбора — конфиг (`min_score`, дефолт 65).

## 3. Правило длины и самодостаточности

Из практики (клипы «до минуты»): каждый кандидат **обязан** укладываться в `max_duration` пресета и быть законченным.

- Если сильный момент длиннее лимита → модель инструктируется **ужать до пуанта** (сдвинуть start ближе к развязке) или **разбить на два** самостоятельных клипа.
- Код-валидатор после LLM: `duration > max` → флаг `too_long` → либо обрезка по правилу, либо отбраковка.
- `duration < min_meaningful_sec` (18 сек, пре-snap) → отбраковка (законченной мысли не бывает в <18 сек). Выше пресетного `min` (15) — иначе no-op.
- `duration < min_clip_duration` (8 сек, пост-snap) — абсолютный минимум после притяжки границ. Snap + padding могут схлопнуть хороший 18-секундный момент; код пробует расширить до ближайшей границы фразы перед отбросом.

Пресеты — из PROJECT_GUIDE (`shorts` 15–90 дефолт / `reels` / `tiktok`).

## 4. Кликбейт-формула заголовка

`title` генерируется тем же вызовом, но **не свободно** — по паттерну, иначе Qwen выдаёт пресный заголовок. Рамка (в промпт):

Паттерны (выбрать подходящий):
- **Скрытое** — «За X скрыт Y», «X на самом деле про Y»
- **Переворот** — «почему [группа] на самом деле [контринтуитив]»
- **Curiosity gap** — обещание ответа без его раскрытия

Обязательные элементы:
- **CAPS на 2–3 эмоциональных словах** (не весь заголовок);
- **1 эмодзи-акцент** по смыслу;
- **обрыв «…»** в конце — провоцирует тап.

Эталон (с рабочего клипа): `ЗА ТРАВМОЙ скрыт ДАР: почему «беглецы» на самом деле СЕРДЕЧНЫЕ 🫀…`

`description` (1–2 фразы): пересказ крючка без раскрытия развязки + эмодзи + 3–5 хэштегов.
Эталон: `Самый неожиданный поворот: за травмой может прятаться ваш ДАР. И если вы сейчас в боли — это не «сломался», это нервная система 🫀 #психотерапия #самооценка #травма #психология`

## 5. Контракт выхода LLM (строгий JSON)

Модель возвращает **только** JSON, без преамбулы и markdown. Парсинг — с fallback на повторный вызов при невалидном JSON (как provider-failover в Meeting→Tasks).

```json
{
  "segments": [
    {
      "start": 124.3,
      "end": 168.9,
      "score": 87,
      "hook": "За травмой всегда скрыт ресурс",
      "title": "ЗА ТРАВМОЙ скрыт ДАР: почему «беглецы» СЕРДЕЧНЫЕ 🫀…",
      "description": "Самый неожиданный поворот… 🫀 #психотерапия #травма #психология",
      "reason": "контринтуитивный тезис + закрытая арка, цитируемо",
      "topic": "травма как ресурс"
    }
  ]
}
```

Пустой `segments: []` — **валидный результат**. «В этом чанке хороших моментов нет» — норма, не ошибка.

> **Примечание:** `segments` здесь — кандидаты от LLM, не поле `segments` манифеста. В манифесте `segments` — явный список окон воспроизведения `[{start, end}]`, появляющийся только при удалении филлеров. Это разные вещи с одним именем на разных этапах.

## 6. Чанкинг длинного транскрипта

60-мин видео ≈ 13K токенов сжатого транскрипта. Несущий лимит Groq free-tier — **OTPM 1000 tok/min** (выход, не публикуется в документации и не виден в заголовках); он определяет `max_tokens`, а не размер чанка. Поэтому чанки держатся **мелкими** (`r0_chunk_tokens` ~1200 токенов): урожай определяется числом запросов, а не размером каждого.

- **Размер чанка** — конфиг `r0_chunk_tokens` (см. `config/r0.yaml`). Мелкий чанк → больше запросов за видео → больше OTPM-окон → выше итоговый recall.
- **Overlap** — соседние чанки перекрываются на ~60 сек, чтобы момент на стыке не потерялся.
- **Адресация по таймкодам** — сегменты из разных чанков сравнимы по абсолютному времени → дедуп работает поверх всех чанков.

## 7. Дедупликация и финальный отбор (код, после всех LLM-вызовов)

1. **Сбор** всех `segments` со всех чанков в один пул.
2. **Дедуп пересечений:** если два сегмента overlap > порога (`dedup_overlap_threshold`) → оставить с большим `score`, второй выкинуть.
3. **Snap границ** к word-level: start/end притянуть к ближайшей границе слова и паузе (не резать посреди слова). Здесь и нужен сохранённый word-level из п.1.
4. **Dangling-start ремонт:** если клип начинается с «висячего» первого слова (не с границы предложения) — сдвинуть start к ближайшей предшествующей границе предложения. Если исправить не удаётся — отбросить кандидата.
5. **Interview mode** (`source_kind: interview`): границы по смене говорящего (тире в транскрипте), вопрос ведущего может служить входом клипа.
6. **Фильтр** по `min_score`, `min_meaningful_sec` (пре-snap), `min_clip_duration` (пост-snap), флагам.
7. **Ранжирование** по score, отбор топ-N (конфиг `max_reels`); отсев записывается в `<манифест>.discarded.json` с причиной отбрасывания каждого кандидата.
8. Запись в манифест, статус `awaiting_review`.

## 8. Token-aware провайдер-слой

Переиспользуется абстракция из Meeting→Tasks (`providers.py`), плюс специфика R0:

- **Adaptive Groq → OpenRouter:** Groq основной; слив на OpenRouter под троттлом, возврат когда Groq остыл.
- **Несущий лимит Groq free-tier — OTPM 1000 tok/min (выход).** Не публикуется в документации и не виден в заголовках `x-ratelimit-*` (те считают входные токены). Диагностика — `scripts/probe_groq.py`; полный разбор — `docs/audit-groq-413.md`.
  - Type A 429 (входной TPM): `remaining-tokens` низкий + `retry-after`. Ждать помогает.
  - Type B 429 (OTPM): `remaining-tokens=8000`, `reset-tokens=1ms`, `retry-after` отсутствует. Ждать бесполезно. Правится `max_tokens` (конфиг `max_output_tokens`).
- **`max_tokens` держать < 1000** (конфиг `max_output_tokens: 900`): резерв ~10% до OTPM. Реальный R0-ответ обычно 200–600 токенов.
- **Бэкофф** на 429: уважение `retry-after` на Type A; на Type B — немедленный слив на OpenRouter.
- **`reasoning_effort=none`** для текущей модели (qwen3): reasoning раздувает выходные токены и бьёт по OTPM. Структурная выборка по рубрике reasoning не требует. Проверять при смене модели — `arl models` покажет актуальный список.
- **Бюджет на видео:** логировать суммарные токены/запросы на один прогон — для контроля дневного потолка (RPD).

## 9. Идемпотентность

Ловушка, уже пойманная в Meeting→Tasks (баг размножения задач) — здесь та же:

- ключ прогона `run_key` = хэш(содержимое источника + `duration_preset`), проверяется **до** анализа. Версии рубрики в ключе **нет**: после правки промпта нужен `--force`;
- транскрипт кэшируется по хэшу аудио **и** параметрам транскрипции (модель, провайдер, хэш промпта) → повторный запуск не перетранскрибирует, а смена промпта кэш инвалидирует;
- сегменты кэшируются по ключу прогона → повторный запуск не плодит дубли клипов;
- перегенерация — только при явном изменении входа или флаге `--force`.

## 11. Ручные аннотации ревью (`arl blocks --apply`)

Ревьюер задаёт параметры клипа в строке оценки. Все аннотации необязательны; что не указано — берётся из умолчаний. Поля независимы, `t:` предпоследним, `d:` последним. Грамматика хранится в одном месте кода, обе выгрузки (verbose и compact) читают её оттуда.

    <блок> <оценка>[+|++|-][@скорость] [| s:N] [| e:N] [| x:N,M] [| h:N[!]] [| c:N-M] [| k:N=слово,...] [| f:0|1] [| t: текст] [| d: текст]
    > N
    > N-M

| Аннотация | Что делает |
|---|---|
| `+`, `++` | Склейка со следующим / с двумя следующими блоками. Внутренние границы не режутся ни снапом, ни ремонтом начала. |
| `-` (перед оценкой) | Склейка с **предыдущим** блоком. `+` на блоке и `-` на следующем — одна склейка. |
| `@N.NN` | Скорость (напр. `@1.15`), к аудио и видео; субтитры пересчитываются. |
| `s:N` / `e:N` | Начало / конец по предложению N (нумерация сквозная через склейку). Явное `s:` не двигается ремонтом начала; явное `e:` не двигается, висячее окончание даёт предупреждение. |
| `x:N,M`, `x:4-6` | Исключить предложения из середины; каждое становится зазором между окнами. |
| `h:N` | Холодный старт: предложение N играет **до** тела клипа как тизер и по умолчанию **убирается из тела** (звучит один раз). При `two_shot` — крупным планом. |
| `h:N!` | То же, но предложение N **остаётся и в теле** (повтор). `!` — явное согласие на повтор; без него повтор запрещён (проверка `source range played twice` → `[ERROR]`). |
| `c:N-M`, `c:2,7` | Крупный план на этих предложениях (`two_shot`). Временное поле; позже — такт `emph`. |
| `k:N=слово,слово;M=слово` | Ключевые слова предложения N выделяются стилем `Keyword` (`subtitle_keywords`). `слово*` — совпадение по префиксу. Промах — предупреждение. |
| `f:0` / `f:1` | Запрет / форсирование удаления филлеров в этом клипе. |
| `t:текст` | Заголовок-плашка, выжигается при рендере. На автоматическом пути пуста. |
| `d:текст` | Подпись для публикации (хэштеги — внутри). |
| строки `>` | Такты: предложения в порядке воспроизведения (перестановка). `s:`/`e:` задают отрезок, внутри которого нумеруются такты. Стык несоседних предложений получает `beat_gap_sec` и смену плана; такт не содержит звука другого такта. Предупреждения: такт начинается со связки или местоимения, отсылающего назад; заканчивается на связке или без терминального знака. Только ручной путь. |

Номера предложений `s:`/`e:`/`x:`/`h:`/`c:`/`k:` совпадают с нумерацией выгрузки (`[1] … [2] …`). Незаконченное предложение помечено `[N]…→` — на нём не ставится `e:`; промпт выгрузки просит ставить самое сильное законченное предложение последним. Неизвестное или битое поле сообщается по номеру строки и игнорируется.

**Явный `e:` на незаконченном предложении** не двигается — клип получает `open_thought` и предупреждение; на вопросе в зал («…, понятно?») — `ends_on_filler`. Без `e:` код ремонтирует конец (продление максимум на одно предложение или откат к предыдущему законченному) — `PROJECT_GUIDE.md`, R0 шаг 7.

**Файлы разметки владельца** — `reviews/*_answer.txt`. Копии для гейта не применяются с `--install`.

## 12. Короткий вызов оценки блоков (M1.6 этап 4)

Альтернатива §5–7 на автоматическом пути: границы кандидатов уже поставил код (блоки), модель только оценивает. Под флагом `use_block_scoring`.

- **Вход:** пачка из 8 блоков с id и текстом; system — рубрика §2, сведённая к видимому в тексте (`prompts/score_system.md`); few-shot — реальные блоки с оценками человека и указанием происхождения (`prompts/score_fewshot.json`).
- **Выход:** `{"scores": [{"id": "b07", "score": 84}]}` — **оценка для каждого id** пачки, включая низкие. Без заголовков, причин и таймкодов (≈120 токенов вместо 900).
- **Полнота:** отсутствующий id → пачка переспрашивается один раз; всё ещё нет → `llm_score=None, reason="missing"` (никогда не ноль). Ошибки провайдера (перегрузка, 5xx, таймаут) повторяются так же. Раньше промпт разрешал не возвращать слабые блоки, и модель выбрасывала 3–5 из 8 — пропуск был неотличим от низкой оценки.
- **Детерминизм:** `temperature: 0` (`score_temperature`); при той же пачке оценка воспроизводится. Опция `score_passes: 2` — второй проход другим составом пачек, усреднение по имеющимся оценкам; по умолчанию 1.
- **После оценки:** `min_score`, дедуп по перекрытию (`dedup_overlap_threshold`), top-N (`max_reels`). Эвристика §5 M1.6 не участвует ни в сортировке, ни в отсечении.
- **Качество (чистые данные, `scripts/eval_scores.py --clean-only`):** AUC 0.77 против 0.57 у эвристики; на 09h 33m все 9 блоков человека в двадцатке, шесть — в первой девятке. Сортировщик, не замена человеку.
