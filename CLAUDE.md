# CLAUDE.md — Авто-Рилс

Агентские инварианты. Читается каждую сессию. Держать коротким и высокосигнальным.

## Что строим

CLI-инструмент: длинное горизонтальное видео (talking-head, статичная камера) → набор вертикальных рилсов 9:16 с выжженными субтитрами и заголовками. Два равноправных режима отбора: **автоматический** (LLM оценивает кандидатов) и **ручной** (человек или модель в любом чате размечает блоки). Облако работает с текстом, локаль рендерит (ffmpeg).

Полная архитектура — `PROJECT_GUIDE.md`. Ядро (выбор моментов) — `R0_SPEC.md`. План и текущий статус — `PLAN.md`. Раскладка — `PROJECT_STRUCTURE.md`.

## Команды

```bash
python3.13 -m venv .venv && .venv/bin/pip install -e ".[dev]"   # установка (editable + pytest)
.venv/bin/python -m pytest                # весь юнит-слой (integration deselect по умолчанию)

.venv/bin/python -m pytest -k dedup -q     # один тест/паттерн по имени
.venv/bin/python -m pytest -m integration  # реальная сеть/faster-whisper
```

- Линтера/форматтера в проекте нет — не выдумывать команду и не добавлять тулинг без спроса.
- `GROQ_API_KEY` нужен только для реального R0/Whisper; юнит-тесты мокают LLM фикстурами и ключа не требуют.
- ffmpeg в `PATH` обязателен, **и собран с libass** — без него нет фильтра `ass`, субтитры не вшиваются, рендер падает на первом клипе. Homebrew-формула `ffmpeg` собрана без libass; ставить из тапа `homebrew-ffmpeg/ffmpeg`. Проверка: `ffmpeg -filters | grep -w ass`.
- **Тесты не пишут в репозиторий.** Autouse-гвард проваливает тест, если он создал, изменил или удалил что-либо под корнем проекта (`manifests/`, `reviews/`, `data/`, `transcripts/`…). `reviews/` не в git — порча там невосстановима. Тесту, которому действительно нужен реальный корень, ставится маркер `@pytest.mark.uses_real_repo` с причиной; молчаливых исключений нет.
- Тест, зависящий от незакоммиченных локальных данных, — не тест. Строить на закоммиченной фикстуре.

## Несущая граница: ОБЛАКО / ЛОКАЛЬ

Делит весь **код** на два тира. **Видео между тирами не передаётся** — облако работает только с текстом (аудио → транскрипт → манифест), исходник живёт на локали, где и рендерится. Это выражено в структуре каталогов (`src/cloud/` vs `src/local/`), не только в соглашении.

Это граница **кода**, не машин. Любая машина может выполнять оба тира; что именно она делает, задаёт её роль (см. «Машины»).

## Жёсткие инварианты (не нарушать)

1. **Determinism-first.** LLM только ранжирует и предлагает кандидатов. Финальные границы реза, отбор, валидацию ставит детерминированный код. Скоры от LLM — подсказка для сортировки, не источник истины.
2. **Grounding обязателен.** Каждое поле от LLM (`start/end/title/...`) привязано к фрагменту транскрипта. Ничего не выдумывается из подразумеваемого.
3. **Пустой массив — валидный результат.** `segments: []` — ожидаемый исход для скучного видео, не ошибка. Но **нулевой урожай при непустом транскрипте — не успех**: источник не архивируется и попадает в сводку отдельной категорией.
4. **Идемпотентность по содержимому.** Транскрипт кэшируется по хэшу аудио **и** параметрам транскрипции (модель, провайдер, хэш промпта). Перед анализом проверяется `run_key` (хэш источника + пресет) против существующих манифестов — совпадение означает «уже обработано», повтор только с `--force`. Версии рубрики в `run_key` **нет**: после правки промпта R0 нужен `--force`, иначе источник ошибочно пропустится.
5. **Ручной выбор не пересматривается кодом.** Для `selection_source: human` работают только **форматирующие** стадии (подтяжка к словам, паддинг, субтитры, ремонт начала и подрезка перед репликой ведущего, подбор скорости). **Решающие** стадии — обрезка длинных, top-N, дедуп, отбрасывание по порогам длительности, плотности или висящему началу — на ручной путь не заводятся вовсе. Всё, на что они сработали бы, становится предупреждением в манифесте. Список стадий ручного пути задан явно и проверяется тестом: новая стадия в автоматическом пути сюда не протекает. Ручную склейку блоков (`+`, `++`, `-`) резать внутри нельзя. Ручной манифест не перезаписывается автоматическим прогоном без `--force`. Файл ревью содержит `# fingerprint:` набора блоков: `--apply` отказывает при несовпадении и называет причину (счёт или границы изменились).
6. **Two-phase.** Phase 1 (выбор+нарезка) до `awaiting_review`, Phase 2 (финальный рендер + выдача) — по approve.
7. **Чек-флаги детерминированы** и считаются от **финальных** границ, не от сырых. Проверка, стоящая до преобразования, которое её обесценивает, — повторяющийся класс багов этого проекта.

## Машины

- **Роль машины** задаётся в `config/render.local.yaml` (не в git): `role: analyze | render | both`. Машина с ролью `analyze` откажется рендерить.
- **Mac** — рабочая машина полного цикла: анализ и рендер. Нужен ffmpeg с **libass** (выжигание субтитров, фильтр `ass`) и **videotoolbox** (напр. сборка из tap `homebrew-ffmpeg`). Кодек `hevc_videotoolbox` (передаётся `--encoder`; поле `codec` в `render.local.yaml` схемой не принимается). Исходники могут лежать на внешнем диске и обрабатываться на месте.
- **Windows (системник)** — рендер и анализ, AMD → `hevc_amf`/`h264_amf`. Под VPN бывают обрывы SSL (`UNEXPECTED_EOF_WHILE_READING` одновременно у обоих провайдеров) — это сеть, не API.
- Между машинами через git ходят только **манифесты и калибровки**. Транскрипты, ревью, кэш, клипы — локальные.

## Технические ограничения

- **Только бесплатные API.** LLM — Groq → OpenRouter failover. Whisper — Groq. Узкое место — **OTPM на R0** (output tokens per minute = 1000 на free-tier; не публикуется, отсутствует в заголовках `x-ratelimit-*`): урожай определяется **числом запросов**, не размером каждого → чанки держать мелкими, `max_tokens` < 1000. Prompt-cache не применим (Groq — только GPT-OSS; снимает вход, а упираемся в выход). Подробно — `docs/audit-groq-413.md`. Ручной режим в лимитах не участвует.
- **Имена моделей протухают молча** — и у Groq, и у OpenRouter. Наличие в каталоге OpenRouter ≠ доступность (часть бесплатных только по своему ключу). Перед диагностикой — `arl models`.
- **Reasoning-выхлоп бьёт по OTPM** → `reasoning_effort=none` для qwen3; gpt-oss принимают только `low/medium/high` — при смене модели проверять.
- **Промпты:** system на английском, вывод на русском.

## Кодовые конвенции

- Python 3.11+. Манифест — единственный контракт между тирами, схема в `src/core/models.py` (Pydantic). Любое изменение схемы — через неё.
- Провайдер-абстракция (`src/cloud/providers.py`): Groq/OpenRouter за одним интерфейсом.
- Конфиг вынесен в YAML (`config/`), не хардкод. Значения конфига **не дублируются в прозу** документации — только ссылка на файл: дублирование уже приводило к расхождению.
- Все пути — от `_project_root()`, никогда относительно текущего каталога. Тест параметризован по парсеру и ловит новую команду с `default='.'`.
- Sidecar-файлы (`.discarded.json`, `.blocks.*.json`, `.failed_chunks.json`…) исключаются из обнаружения манифестов централизованно; тест выводит список суффиксов из писателей, а не из константы.

## Дисциплина разработки

- **TDD.** Сначала тест на детерминированный слой, потом код. LLM мокается фикстурами реальных ответов — не рукописным JSON: рукописные фикстуры пропустили баг формата ответа OpenRouter.
- **Отчёт — не доказательство.** Заявленное улучшение проверяется по файлам на диске (`manifests/`, `transcripts/`, готовые клипы), а не по сводке.
- **Качество проверяется глазами на видео, не только по тексту.** Тишина внутри клипа, отсылка к предмету вне кадра, мысль, продолжающаяся за концом, в тексте не видны.
- **Инкрементально, со стоп-чеками.** Структурное изменение сначала доказывает, что старые данные дают тот же результат, — потом надстройка.
- **Минимализм.** Простейшее, что работает.
