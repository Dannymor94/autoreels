## 1. Решения по P1 Sol R2

### P1-R2-1 — A3: строгое начало после CLI-укорочения

**Путь в замороженном коде.**
- `_drop_sentences` (`__main__.py:1159–1183`) убирает фразы и оставляет `units` как были.
- M173 (`:8980–8991`) может убрать первую звучащую фразу.
- Montage apply (`:6822`) строгое начало не проверяет.
- M167 (`:1136`) убирает только последнюю фразу, поэтому начало он не меняет.

**Инвариант.** У принятого montage-предложения с `fix_body_start` первая звучащая фраза проходит тот же семантический предикат, что в `context_start`.

**Решение (AD §2.2).**
- Укорочение принимается обратимо: проверка идёт до любой мутации `pr`.
- Проверяется семантика новой первой фразы, если она сменилась. Предикат тот же `_start_why[1]`, с тем же исключением для вопроса с «?».
- Склейка (timing) не перепроверяется: это soft-правило M145.
- Проверка не прошла → укорочение не берётся, `pr` не меняется, добавляется заметка, кандидат уходит в `rejected` с исходной ошибкой.
- `require_morph()` вызывается при входе в montage-отбор.
- `core` точный через `Proposal.seed_id`.
- Происхождение: `not scenario`, то есть main и weak-seed; сценарист не затронут.

**Будущий allowlist.** Слайсы A3 в `_try_accept` (`:8966–8978`, `:8980–8991`), точка входа, `Proposal.seed_id`.

**Оракулы.**
- FB: FX-2S (`1.1-2 2.1` → `1.2 2.1`, где `1.2` = «Да, конечно.») принимается при fake check.
- PA: укорочение не взято → `rejected` с заметкой.
- Контроли:
  - допустимое укорочение берётся;
  - новая первая фраза-вопрос берётся;
  - нет pymorphy3 → `RuntimeError` до первого приёма;
  - start только со склейкой берётся;
  - покрыты main и weak-seed;
  - пул сценариста не изменён.
- OFF: замороженный порядок операторов (обязательство теста).

**Уровень.** ANALYTIC; FX-2S — REPORTED (helper).

### P1-R2-3 — A8: изоляция legacy-финализации

**Путь в замороженном коде.**
- `_forms` общий (`:8864`); его используют `_plate`/`headline` (`:8893–8901`).
- `headline` меняет выбор и сам `Proposal` (`autocut.py:1839–1848`).
- Позднее переписывание плашек (`:9076–9083`), короткие версии (`:9084–9103`), печать статистики (`:9104–9107`).

**Инвариант.** Legacy-поля, строки `M1…Mk` и последовательность запросов к провайдеру при выключенном флаге — префикс последовательности при включённом. Так при любом исходе для вариантов.

**Решение (AD §2.4.1–2.4.3).**
- Инвентаризация всего цикла CLI — 16 шагов.
- Граница фазы L проходит после шага 12 (позднее переписывание плашек, короткие версии, печать).
- G1 только собирает дескрипторы: без моделей и callback'ов. G2 строит варианты в начале фазы V, и вызовы судьи попадают туда же.
- Отдельные списки, судьбы и учёт; `_counted` варианты исключает.
- `_forms` продолжает legacy-список, но legacy-заголовки к этому моменту окончательны.
- Без коротких версий для вариантов.
- Persistent `_jstore` и раздельные хранилища для A/B (AQ5).
- Монотонность обещана только при принятом полном цикле.

**Будущий allowlist.** `propose`: `variant_descs_out`, `variant_descs`; CLI: G1, фаза V, цели `_try_accept`, `_counted`, раздел черновика.

**Оракулы.**
- FX-1P: fake provider, побайтное сравнение legacy и префикс запросов. Варианты приняты / отклонены / hookless / только рассмотрены; greedy и global; fill и hookless.
- FX-1H — из R2.

**Уровень.** ANALYTIC; воспроизведение Sol с `_forms` — REPORTED.

## 3. Бюджет вызовов модели и сложность (по конфигурации)

Обозначения:
- `J` — судья контекста включён (`context_start ∧ context_judge`);
- `r` — повторы судьи на запрос (`make_judge`: 1 повтор → ×2);
- `S` — число зёрен, дошедших до `context_start`;
- `B = context_back`, `L = context_later ? (строк в мысли − 1) : 0`;
- `P` — размер пула (`clips × check_pool` + добавленные слабые зёрна);
- `N` — кандидаты, до которых дошёл отбор (≤ P);
- `A` — принятые;
- `K = seed_alt_max`.

Кэш судей (в памяти и `_jstore`) может только уменьшить эти числа.

| Источник | Верхняя граница логических запросов |
|---|---|
| `propose` main (+weak-seed) | `J · S · 6 · (2 + B + L) · r` (6 итераций `context_start`) |
| A3: перепроверка начала после M173 | `J · N · 2 · r` |
| polish одного кандидата | `hook_judge ? hook_judge_top·r : 0` + `1` (rank_hooks) + `hook_title ? 1 : 0` (headline) + `(keywords ∧ source≠rule) ? 1 : 0` |
| швы (`seam_check`) | `min(P, 2·clips)` |
| позднее переписывание плашек M112 | `(hook_title ∧ plate_hookless) ? A : 0` |
| A8 G2 (судья контекста для вариантов) | `J · K · 6 · (2 + B + L) · r` |
| A8 фаза V | швы `≤ K`; polish `≤ K ·` (строка polish); переписывание плашек `≤ R` |

Повторы транспорта (`max_retries` провайдера) идут поверх логических запросов.

В производственной конфигурации (`context_judge: false`) первые две строки и строка A8 G2 равны 0.

**Сложность.**
- TC9a: не больше `len(units)+2` итераций, время O(n²).
- `_final_integrity`: O(7·|clip| + |EST|).
- Перепроверка CLI: не больше 2+2 укорочений на кандидата.
- M231: O(7·|clip|) на зерно; callback'и не вызываются.
