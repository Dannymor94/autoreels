## 1. Итог

Для всех 9 подслучаев FIX_NOW даны детерминированные ограниченные решения. Каждое под своим флагом (OFF = прежний код) и с оракулами fail-before / pass-after / negative / OFF:
- 6 решений обязательны: TC5, TC7, TC8a, TC2, TC9a, TC1;
- TC8b — тест, закрепляющий текущий fail-closed: причина уже пишется в `rhythm_out`, и формулировка контракта «тихий drop» неточна;
- 3 решения ждут владельца: Q3/TC3, Q6/TC8b-recovery, Q7-b/TC9b.

Выбрана гибридная схема: проверка стоит сразу после того преобразования, которое может нарушить инвариант, и пишет в уже существующий канал причин. Полную перестройку «generate → finalize → validate → select» не делаем. Обоснование — инвентаризация в `ARCHITECTURE_DECISIONS.md` §0: в `propose` ровно три места, где инвариант не проверяется. Это шаг (a) `context_start` без min_sec (TC5), добавление вопроса в конец в `fit_rhythm` (TC8a) и удаление опоры в `fit_rhythm` (TC7).

## 5. Открытые ARCH_QUESTION (для Sol и координатора)

1. **Сигнатура `propose(trace=None)` в M231.** Это аддитивный keyword с поведением OFF = прежний код. Q8 запрещает только сигнатуры `teaser_misses` и weak-seed. Нужно подтверждение, что `trace` допустим в M231.
2. **Имена флагов** (`fix_context_min_sec`, `fix_rhythm_integrity`, `fix_body_start`, `fix_passage_side`, `hook_clauses_autocut`, `passage_answer`, `end_trim_recover`, `seed_alt`, `seed_alt_max`) — PROVISIONAL. Нужно решение координатора: по флагу на пакет (предложено) или иначе.
3. **A8 при пуле > 30.** Монотонность доказана только для `greedy` и точного `global`. Выше 30 включать только после событий M231 `select`/`fate`.
4. **Мера длительности.** TC5 проверяет по `_dur`, как весь `propose`. Перевод на секунды фраз — M232-B, только если `secs_delta` из M231 меняет вердикты.
5. **Replay.** У A5 и A8 новые кандидаты при доводке дадут новые запросы к судьям, и `ARL_LLM_CACHE=replay` на них упадёт (так задумано). Для A/B нужен прогон `record` на бесплатных моделях с согласия владельца. Это рамки M237.
6. **Документальная правка реестра.** В TC8b формулировка «тихий drop» неточна: M225 C показал непустой `rhythm_out`. Правка только в документах, без нового цикла.

## 6. Блокер публикации

В этой среде нет прав записи в `origin`: ни токена, ни credential helper. Поэтому коммит создан локально поверх `ff155de…` и передан владельцу git-bundle. Fast-forward публикация того же коммита сохраняет его SHA:

```bash
git fetch m230-arch-r1.bundle m230-arch-r1:refs/heads/m230-arch-r1
git push origin m230-arch-r1:handoff        # fast-forward с ff155de…
git rev-parse origin/handoff                 # = FINAL_HANDOFF_SHA из ответа
```

После публикации — стоп для независимого Sol QA архитектуры и решений владельца. Реализация не начинается до отдельного решения координатора.
