# M133 — ревью кода и состояния папки проекта (ТОЛЬКО ЧТЕНИЕ, параллельный агент)

Параллельно может работать MAIN (рендер, коммиты). Поэтому эта задача **ничего не меняет**.

## Запреты (нарушение = остановиться и написать в отчёт)
- Не менять, не удалять, не перемещать ни один файл проекта. Писать можно только в `handoff/m133/` (он в .gitignore).
- Не коммитить, не делать checkout/reset/stash/pull в рабочей копии. Можно только `git status`, `git log`, `git diff`, `git show`, `git ls-files`, `git fetch`.
- Не запускать pytest, рендер, `arl`/`autoreels` (кроме `-h`), сеть к LLM, gamebox.
- Не открывать `.env`. Содержимое `reviews/*_answer.txt` не цитировать — только имена файлов.

## Шаги

1. `bash handoff/bin/take.sh m133`
2. **Папка.** `python3 handoff/m133/folder_audit.py > handoff/m133/folder_audit.md` (скрипт только читает). Прочитай вывод и выпиши в отчёт:
   - незакоммиченные/неотслеживаемые файлы в git (что это и откуда, по имени/дате);
   - что занимает место (топ папок, `_gate` по источникам, старые гейты > 14 дней);
   - мусор: tmp/partial/lock/bak, пустые или нечитаемые манифесты, сироты в `transcripts/`, лишнее в `reviews/` (бэкапы, «other»);
   - чего не хватает: `render.local.yaml`, модель YuNet, исходники манифестов вне `inputs*/`.
   Для каждого пункта — предложение «удалить / оставить / в архив», с причиной. **Не удалять.**
3. **Код — проверка статического скана** `handoff/m133/static_scan.md` (vulture, сделал ассистент на `c9bd55a`). Для каждой строки разделов A–D: `grep -rn "<имя>" src tests config` и классифицируй одним словом:
   - `dead` — нигде не используется, можно удалить;
   - `dynamic` — используется неявно (поле Pydantic/манифеста, обработчик argparse, метод HTTP-сервера, читается через getattr/yaml);
   - `test-only` — вызывают только тесты (вопрос: оставить как API или удалить вместе с тестом);
   - `config-noop` (раздел B) — поле конфига, которое код не читает: YAML-ручка ничего не делает → нарушение «конфиг вынесен, а не хардкод», в отчёт как дефект;
   - `swallow-ok` / `swallow-bad` (раздел D) — глушение исключения оправдано или прячет ошибку (CLAUDE.md: «проверка без тихих исключений»).
   Формат: таблица `файл:строка | имя | класс | одна фраза почему`.
4. **Код — ручной просмотр** (только чтение, ~30 мин, не больше): `cloud/autocut.py`, `cloud/scenario.py`, `cloud/plan.py`, `local/autocrop.py`, `render.py` функции `_reel_framing`/`_source_face`. Ищи по CLAUDE.md:
   - нарушения инвариантов (LLM решает вместо кода; голые конструкторы `Segment`/`Word`; время из зазоров Whisper; проверка до преобразования; пути не от `_project_root()`; значения-константы, которым место в config);
   - дублирование логики между autocut/scenario/plan;
   - ветки под флагами, которые уже всегда включены (флаг можно убрать) — только список.
   Каждая находка: `файл:строка`, что не так, какой инвариант, насколько срочно (высокая/средняя/низкая). Без правок.
5. Отчёт `handoff/m133/REPORT.md`: разделы «Папка», «Скан», «Ручной просмотр», «Предлагаемые действия» (нумерованный список, каждое — отдельной будущей задачей). Отправка (своя временная папка, чтобы не столкнуться с MAIN):
   `TMPDIR=$(mktemp -d) bash handoff/bin/report.sh m133 folder_audit.md`
   Владельцу — одна строка: сколько находок высокой срочности и где отчёт.
