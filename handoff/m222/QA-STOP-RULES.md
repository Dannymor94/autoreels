# M222–M237 — протокол QA без бесконечных повторов (дополнение к PLAN-M222-V2)

Дата: 2026-11-18. Цель — проверяемое продвижение по задачам без превращения каждого технического сомнения в новый цикл R3/R4/R5.

## 1. Не смешивать уровни доказательства

| Уровень | Что доказано | Допустимая формулировка |
|---|---|---|
| CLI | Реальный `cmd_autocut()`/CLI с фактической конфигурацией, исходными функциями и обратными вызовами; зафиксированы вход/выход и ветви | `CLI_CONFIRMED` для конкретного наблюдаемого эффекта |
| HELPER | Прямая оригинальная функция, синтетические параметры/колбэки; реальные ветви функции исполнены | `HELPER_CONFIRMED`; **не** `CLI_CONFIRMED` |
| STATIC | Сигнатура, условие/ветка исходного кода | `STATIC_CONFIRMED` как механизм, не автоматически пользовательский эффект |
| NOT_REPRODUCED | Вход заблокирован валидатором, нужной безопасной медиа-среды нет, эффект не появился | `NOT_REPRODUCED`, точная причина, команда и проверенный инвариант |
| INTENTIONAL | Подтверждённый продуктовый лимит/дизайн (например `hook_judge_top=6`) | `INTENTIONAL`, без автоматического фикса |

**Правило честности:** смешанный кейс описывается как несколько утверждений с собственным уровнем доказательства. Например, `#5: HELPER_CONFIRMED, CLI_NOT_REPRODUCED`; нельзя объединить в общий `CONFIRMED VIA CLI`. Тестовый `exit 0` означает, что прошли *утверждения теста*, а не что достигнут production CLI.

## 2. Проверка по неизменяемому SHA

Каждое ревью обязано указать:
- `main SHA`, `handoff evidence SHA`, Git blob SHA скрипта и отчёта;
- входной режим (важно: `auto_mode: scenario` по умолчанию; для `propose` явно нужна ветка autocut), `generator`, `min_sec`, `end_tone`, `rhythm`, `hook_clauses`;
- реальные `argv`/параметры и **источник** параметров (CLI или вручную `AutoParams`);
- `expected/actual`, stdout/stderr, фактический код завершения и SHA256 опубликованных файлов;
- реальные пути проверки: `propose` → repair → selection → validator, если заявляется соответствующий эффект. `spy` обязан вызывать оригинал.

Для утверждения о речи/паузе нужны временные метки слов из синтетического выравнивания и финальный планируемый интервал; `t1-t0`, `sum(sentence.sec)` и слышимая длительность — **разные показатели**. Рендер не разрешён.

## 3. Стоп-правило: максимум два целевых повторных захода

1. После первичной сдачи координатор даёт **один** приоритетный список `P0/P1` и формулирует достаточный для PASS тест до следующей работы. Не добавлять требования после запуска, если не обнаружен новый реальный риск.
2. **R1 и R2 — максимум две целевые переделки одного доказательства.** На каждой переделке: `CLOSED`, `STILL_OPEN`, `NOT_REPRODUCED` по каждому замечанию. Не повторять прежние успешные тесты без изменений, которые их затрагивают.
3. Если после R2 production-путь безопасно недоступен или гипотеза не воспроизводится, **остановить этот кейс**. Записать в M228 как `NOT_REPRODUCED`/`HELPER_ONLY` с препятствием. Не выдумывать медиа, не менять конфиг ради красивого PASS и не выпускать R3 с тем же требованием.
4. Независимый Sol выдаёт `PASS` **с явно ограниченной областью доказательств**, если закрыта проверка того, *что реально было исследовано*, а непроверенное не заявлено подтверждённым. Иначе `CHANGES_REQUIRED` с **новым воспроизводимым основанием** или `BLOCKED` с точным отсутствующим условием. **Нельзя объявлять PASS за Sol.**
5. Если Sol не может принять даже честный ограниченный пакет, не делать третий круг автоматически: эскалировать архитектурную/продуктовую границу владельцу в M228 и перейти к *неконфликтующей подготовке*, без правки production-кода и без незаконного обхода гейтов.

## 4. Что делать параллельно

- **Sonnet** — один активный Stage A репро (сейчас M224-R2). Не параллелить правки `autocut.py` из других задач.
- **ChatGPT** — статические префлайты последующих кейсов, схемы тестов, контроль SHA/лога, проверка отсутствия изменений в `main`, подготовка M228 evidence ledger.
- **Sol** — независимый разбор *зафиксированного* пакета после публикации; никаких догадок на основе словесного отчёта.
- **M225–M228:** подготовку разрешено вести заранее; **исполнять** их Stage A по утверждённой очереди и приёмке предыдущего гейта. **M229–M237:** только после явных зависимостей и разрешённых PR.

## 5. Никаких ложных критериев

Инструмент `handoff/bin/evidence_consistency.py` — проверка целостности SHA256, файлов и логов, **не независимый тест качества и не доказательство покрытия CLI**. Он опционален для исторических пакетов и рекомендован для новых. Не устраивать новый цикл только из-за отсутствия этого метафайла в старых задачах.

## 6. Решение на каждой сдаче

Ответ координатора строго: `GATE=PASS|CHANGES_REQUIRED|BLOCKED`; `SCOPE=...`; `NEW_FINDINGS=...`; `NEXT=...`; `STOP_REPEATING=...`. Повторный запрос на те же данные без нового основания запрещён. Модельные API, полный рендер и изменения пользовательских файлов запрещены прежними инвариантами.
