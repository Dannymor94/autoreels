# M222–M237 — декомпозиция для владельца (русский)

## Правила очереди

- Sonnet 4.6 **исполняет**; Sol 6.1 **независимо проверяет**; ChatGPT **ставит задачи/принимает технические отчёты**; только назначенный интегратор после PASS переносит изменения в `main`; владелец утверждает включение и качество. Если нужно переосмысление алгоритма — архитектурное ревью более сильным агентом на M230.
- Сначала M222a: источники, правка `CLAUDE.md`, baseline. Затем M223–M228: **доказательства без исправления поведения**. Далее M229–M236: последовательная реализация. M237: A/B и продуктовая приёмка.
- Отчёты только на русском, задачи `TASK-*.md` для Sonnet — на английском. Код и комментарии остаются в стиле репозитория.

## Критический путь и параллелизм

1. M222a запускается первым и блокирует всё остальное. Никаких мутаций исходников без проверки источников и политики.
2. M223–M227 можно вести в независимых worktree одновременно **только как тесты/доказательства**, если исполнителей несколько. С одной Sonnet-сессией выполняются по очереди. Sol проверяет уже сданную задачу, пока Sonnet может заниматься другой **независимой read-only** задачей.
3. M228 сводит доказательства. Неподтверждённые находки не чинятся.
4. M229 → M230 → M231 → M232 → M233 → M234 → M235 → M236 идут **последовательно**, без параллельного изменения `propose()`.
5. M237 только после интеграции, без фальшивого replay. Даже если набор улучшился по числам, флаги включаются только с решением владельца.

## Что именно считать доказательством

- Путь CLI на той же конфигурации `config/r0.yaml`, по которой реально работает запуск (включая `hook_clauses:true` и `auto_mode`); сравнение с прямым хелпером дополняет, но не заменяет CLI.
- Изолированный вход с refs, временем, ролями и оценками; команда; stdout/stderr; код возврата отдельно; фактический vs ожидаемый результат. Для нового поведения — failing regression на baseline; затем passing на изменённой ветке.
- `tests/` содержит постоянные тесты **только с закоммиченными фикстурами**. В `handoff/` допустимы временные воспроизводящие скрипты и логи; они не считаются репозиторными тестами.
- Реальное перечисление baseline failures сохраняется в `handoff/m222/baseline-failures.txt`; Sol сравнивает множества через `handoff/m222/compare_failures.py`.
- Для A/B: детерминированный слой без судей — обязательный, модельный `record→replay` — дополнительный с отдельным учётом новых промптов. Сравнивать исчезнувшие и добавленные клипы, не только пересечения.

## Продуктовые ограничения

Нет полного рендера, артефакты владельца не меняем, платные API не вызываем. В `CLAUDE.md` временно описана обязанность Sonnet писать код, а Sol его ревьюить. Все новые флаги выключены до продуктового решения; исправление существующего `hook_clauses` не получает второго флага. Для расширения пула обязательно до изменения измерить бюджет и верхнюю границу.
