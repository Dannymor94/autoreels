# Проверенная конфигурация исходной базы (чтение GitHub, main f92b4d2)

При подготовке пакета по `config/r0.yaml` подтверждены следующие настройки автонарезки:

| Ключ | Значение | Значение для тестов |
|---|---|---|
| `auto_mode` | `scenario` | `arl auto` по умолчанию **не** доказывает путь `propose()`; надо явно выбрать путь `autocut`/montage через реально существующий аргумент CLI, сначала проверив `--help` |
| `generator` | `mixed` | проверять раннее взятие `taken/used_seeds` именно при таком генераторе; альтернативные режимы — отдельный кейс |
| `hook_clauses` | `true` | #3 требует проверки отсутствующей передачи callbacks из CLI |
| `start_strict` | `true` | #2 |
| `answer_start` | `true` | #2 |
| `start_morph` | `true` | #2 |
| `context_judge` | `false` | детерминированный baseline начала не должен вызывать судью |
| `hook_judge_top` | `6` | #10 — ограниченный бюджет; не объявлять багом без замера |
| `hookless_last` | `true` | отсутствие hook может менять очередность отбора |
| `close_by` | `sound` | претендовать на отсутствие дедуп по played-refs только после проверки фактического этапа |
| `select` | `global` | #4 надо воспроизвести в пути CLI с поздними отказами |
| `check_pool` | `3` | до генерации альтернатив и роста стоимости обязателен замер |

Это не заменяет загрузку настроек в воспроизводящем тесте и не фиксирует константы навсегда: Sonnet обязан прочитать фактическую конфигурацию из рабочей базы и указать её SHA. Названия аргументов `arl autocut/arl auto` проверить командой `--help`, не угадывать.
