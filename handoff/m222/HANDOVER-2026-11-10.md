# Передача дел — autoreels, 2–10 ноября 2026

Для следующего чата. Что делали, зачем, к чему пришли и что ждёт дальше. Проверяемые факты — коммиты в `main` и файлы в ветке `handoff`.

## С чего начали
**30 октября платный API перестал отвечать** (Claude: HTTP 403, ключ отклонён). Отчёты при этом выглядели нормально: прогон читался как «из кэша, $0», потому что код печатал только имя ошибки, а строка расхода при нуле удачных запросов не выводилась совсем. Поломка прожила два дня незамеченной — в одном прогоне падал 151 запрос: заголовки, ключевые слова, стыки, крючки.

Владелец, 2 ноября: **«максимально детерминированно»**, и отдельно — только улучшение механик, без нового рендера и пересборки клипов.

## Куда шли
Две цели:
1. **Сделать невидимое видимым.** Главный урок периода: дефекты живут месяцами не потому, что их трудно починить, а потому, что их никто не видит. Поломка API — два дня. Дефект резов M79 — месяц. Клип «Алгоритм или эмпатия» исчезал молча, в консоли стояло только число.
2. **Снять зависимость от платного API**, не теряя качества и не превращая код в догадки: каждая замена модели правилом проверяется замером на размеченных данных владельца, и если сигнала нет — правило не включается.

## К чему пришли

### Видимость
- **M201:** у каждой строки «модель не ответила» есть текст ошибки; строка расхода Claude считает отказы.
- **M202, M204, M206:** кэш ответов моделей (`record` / `replay`, `ARL_LLM_CACHE`). Прогон повторяется байт в байт — A/B правки кода показывает разницу **только от кода**. Проверено: record → replay дал 7/7 одинаковых черновиков.
- **M202, M217:** каждый ушедший кандидат и каждый отказ планировщика печатается с причиной (`✗` проверка, `≈` похож, `○` без крючка, `…` не дошла очередь; перекрытие, доля выреза, интервал, отмена правкой коротких планов).

### Работа без платного API
- **M203, M204:** ключевые слова `k:` ставит правило (последняя фраза → первая → середина, последнее содержательное слово). Замер на разметке владельца: 31 % попаданий слово в слово против 6 % у случайного выбора. Включено, не больше 2 на клип.
- **M204:** в режиме сценариста плашки, `k:`, стыки и крючки идут на модель прогона (бесплатные Groq → OpenRouter), а не на Sonnet. До этого при 403 они молча пропадали.
- **M207, M215:** сценарист через **любой чат**: задание одним файлом `exchange/<ист>.scenario.md` → чат → ответ в `exchange/<ист>.scenario.answer.txt` → `arl scenario-check` → сборка. Проверено: путь через чат дал 7/7 черновиков байт в байт как через API. С `--on-remote` файлы ездят сами, без `scp`.
- **M208, M209:** паспорт карты (роль, сила, темы) считают правила там, где модель не ответила. Полная карта не меняется, неполная больше не останавливает прогон.

### Отбор
- **M205, M206:** похожесть клипов — по общим **сыгранным фразам**, а не по мыслям карты (то есть не по разметке модели); отбор — глобальный набор с наибольшей суммой оценок. На 7 старых источниках: 51 → 54 клипа, «Алгоритм» вернулся. На новом видео глобальный отбор дал сумму 1679 против 1613.

### Машины и приём
- **M213, M214a:** `arl auto <ссылка или папка Я.Диска>` — видео папки по одному, вопрос об удалении один раз в начале (владелец решил исходники не удалять: на gamebox 3,1 ТБ, а рендер потом потребует файл).
- **M214b:** на gamebox поднят VPN **только для autoreels** (Xray, локальный прокси; РФ и локальная сеть напрямую), доставлены `torch`, `pymorphy3`, модель выравнивания, ключи бесплатных моделей.
- **M214c:** `arl auto … --on-remote` — весь прогон на gamebox, видео остаётся там, на Mac приезжают только тексты.

### Рендер
- **M212b–M212d:** тревога целостности на gamebox оказалась **не ложной**: `h264_vaapi` изредка ставит на место кадра 12-байтовый пакет только со служебным SEI (разбор сохранённого клипа `ab192/r03`: 4120 пакетов, 4119 кадров). Теперь такой клип автоматически перерисовывается `libx264`, у каждой ошибки есть `rNN.error.txt`, прежние ошибки уходят в `_errors/`.
- **M215, M217:** длинная пауза режется в обход интервала, но не вплотную к другой смене картинки. После разбора Codex выяснилось, что предел мерил расстояние **в исходном времени**, а после вырезов куски съезжают: между двумя скачками оставалось 0,67 с речи. Флаг `gaps_after_cuts` считает интервал по сыгранному времени и добавляет конец окна в смены. **Выключен — ждёт проверки на живом рендере.**

### Что решили НЕ делать (это тоже результат)
Каждое — по замеру, а не по мнению:
- **стыки правилами** — правила начала клипа помечают 33 % и плохих стыков, и хороших: сигнала нет;
- **крючки правилами** — выбор кода уже детерминирован, эталона мало (холодный старт у владельца в 3 клипах из 68);
- **плашки из слов клипа** — 20 % совпадения с плашками владельца против 8 % у случайного куска; плашки владельца — пересказ, а не цитата;
- **голос в оценке клипа** (M211) — AUC 0,47–0,55, то есть голос не отличает мысли из клипов владельца; сила по модели — 0,68;
- **паспорт карты целиком правилами** (M208) — 33 клипа владельца из 56 против 36 у модели; правила оставлены как запасной вариант;
- **нумерация блоков по карте речи** — по замеру M134 совпали бы 13 границ из 72, а разметка владельца перестала бы применяться.

### Порядок и документация
- **M216:** формат задач для агентов записан в `CLAUDE.md` (владелец: «чтобы справились Sonnet 4.6 и Codex»): проверка печатает `OK`/`FAIL` вместо чисел для сверки глазами, код выхода берётся отдельно от вывода (без `| tee`), нестрогие ожидания помечены, каждая часть самостоятельна, код приходит готовым патчем, Codex — разбор, Sonnet — исполнение.

## Как здесь работают
- Ассистент пишет задачи в ветку `handoff` (`handoff/mNN/TASK-MNN.md` + патч, уже прогнанный у ассистента). Агент на Mac применяет, прогоняет тесты, коммитит в `main`, кладёт отчёт обратно.
