# Ревью для Codex: противоречия между правилами резов (`src/autoreels/cloud/plan.py`)

## Что это за код
`build_manual_plan` строит план клипа: из размеченных предложений получаются окна (`PlannedWindow`), внутри окна выбираются вырезы — паузы и слова-паразиты. Каждый вырез проходит набор правил. Решение принимает код, модель сюда не вмешивается.

Правила (все в одном цикле по кандидатам, отсортированным по длине):
- `min_cut_spacing_sec` — два реза не ближе этого друг к другу;
- `change_gap_sec` (M72) — рез не ближе этого к любой другой смене картинки (шов, смена плана, другой рез);
- `max_removed_share` — доля вырезанного от длины окна;
- `jump_max` / `jump_mask` / `mask_min_gap_sec` — видимый скачок маскируется сменой плана;
- `long_pause_sec` (M79) — пауза длиннее порога режется **в обход** интервала и доли;
- `long_pause_gap_sec` (M215) — но не ближе этого к другой смене;
- `filler_word_cut` (M126) — отдельные слова-паразиты;
- перекрытие уже взятых вырезов (M136).

## Что уже ломалось
- **M136:** вырез паразита (M126) и длинная пауза рядом покрывали одну и ту же тишину. Длинная пауза обходит правила интервала, поэтому брались оба, и кусок между ними выходил перевёрнутым: `segment 1 empty/reversed`, весь черновик не применялся.
- **M79 → M215:** длинные паузы в обход правил собирали очередь резов в соседних клипах (r03, r08, r09, r12). Введён предел `long_pause_gap_sec`.

Обе беды одного рода: **правило-исключение обходит ограничитель, и два правила дают несовместимый результат.**

## Вопросы
1. Есть ли ещё пары правил, где одно обходит другое и это может дать противоречивый план: пустой или перевёрнутый кусок, вырез за границей окна, перекрытие, рез внутри уже вырезанного?
2. Влияет ли порядок обработки кандидатов (по длине, затем по порядку) на итог так, что перестановка двух равных по длине кандидатов меняет план? Детерминированность важна: один и тот же вход должен давать один и тот же выход.
3. Есть ли правила, чьё совместное срабатывание даёт результат, который не видно ни в одном счётчике (`cuts_skipped`, `cuts_spaced`, `cuts_long`, `cuts_long_spaced`)? Невидимые решения — главная причина, по которой M79 прожил месяц.
4. Места, где сравнение времён идёт без допуска (`_EPS`) и возможна ошибка на границе.

## Форма ответа
Список находок, каждая:

- что покажет пользователь — пустой кусок, лишний рез, несчитанное решение;
