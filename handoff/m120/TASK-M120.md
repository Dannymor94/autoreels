# TASK M120 (окно MAIN, Mac): правило скачков (гибкие куски), смешанная сборка «отрезок + петля + вывод», судья начала вне отбора, исправление заметки «модель против»

Файлы — в ветке `handoff`, папка `handoff/m120/`: `TASK-M120.md`, `m120-rhythm.patch`, `owner_rhythm.py`, `gen_compare.py`, `owner_drafts.py`.

**Ставится поверх M119** (fd2f78d). Одна сессия, без фоновых задач. Около 35 минут. gamebox не нужен.

## Зачем
Владелец о сборках: «смысловые перестановки — чтобы было интересно смотреть, можно повторение, но без частых быстрых скачков, чтобы внимание не воспринимало, что что-то скачет. Касательно кусков нужно продумать гибкий алгоритм».

Как монтирует сам владелец (66 клипов):
- 48 клипов — без скачков;
- 12 — с одним скачком, 6 — с двумя, с тремя и больше нет ни одного;
- кусок после далёкого скачка длится не меньше 12 с;
- последний кусок (вывод, точка) бывает коротким — от 6 с.

Сейчас автомонтаж допускает до 3 скачков и куски любой длины.

Итоги m119:
- Судья начала не совпадает со вкусом владельца. Начала владельца Haiku принимает в 35% случаев, начала любых кандидатов — в 36%; Groq — 37% и 36%. По его оценке отбор становится случайным.
- В заметке «модель против» бывала причина от правил с другой фразы: «И работай дальше.» — ссылка назад «и…».
- Без модели лучше всех покрывают клипы владельца отрезки подряд: 36 из 66 против 14 сейчас.

Патч (всё под флагами, выключено → прежний выход; проверено побайтово на черновике IMG_6848 без модели):
- `autocut.rhythm` — правило скачков, одно для всех сборок:
  - скачок — промежуток в исходнике больше `rhythm_jump_sec` или шаг назад;
  - скачков не больше `rhythm_max_jumps`;
  - кусок после скачка должен успеть «осесть»: после короткого пропуска нужно меньше, чем после далёкого скачка (от `rhythm_settle_near` до `rhythm_settle_far`);
  - последний кусок — вывод — может быть вдвое короче;
  - кусок, который не держит правило, дополняется соседними мыслями той же темы или убирается, если в нём нет зерна и вывода; иначе сборки нет, и она уходит в черновик отдельным списком;
  - проверка — на окончательной сборке, после правки начала и конца;
  - правило написано по клипам владельца: проходят 65 из 66. Не проходит один клип старого формата, где первые 3 с — крючок; у autocut крючок отдельно (`h:`).
- `autocut.generator: mixed` — основа — отрезок подряд (как passage). К нему добавляются вопрос-петля из другого места (если есть) и вывод из более позднего места той же темы, если в отрезке вывода нет. Это смысловая перестановка с опорой на сюжет «вопрос → отрезок → вывод». Повторение уже есть: тизер `h:…!`.
- `start_judge: rank`: сомнение — это ответ модели на ту фразу, с которой сборка действительно начинается.
- Судья начала в прогонах этой задачи выключен (`--ac context_judge=false`): начало проверяют только правила, как в замере без модели. Кода для этого не нужно, поле уже есть.

## Правила
1. Любой шаг упал или не совпал с «Ожидается» → **СТОП**: номер шага, команда, последние 40 строк. Ничего не чинить. Расхождение чисел — не СТОП, это замер.
2. Перед стартом не должно идти других `arl` и рендера. pytest — только в шаге 1. Если в pytest упал только `tests/test_menu_bash.py::test_menu_settings_profile_picker_and_cancel` — перезапустить этот тест один раз. Прошёл — не СТОП (тест зависит от времени), отметить в отчёте.
3. Не трогать:
   - `reviews/*_answer.txt`, `reviews/*.review.json`, `reviews/verdicts.jsonl`;
   - черновики прошлых задач;
   - манифест `PXL_20260729_085910095_34f06abf.json`.

   Черновики этой задачи — только новые файлы `reviews/<stem>_auto_m120-*.txt`. `arl tx-use`, `arl auto`, `arl render`, `arl export` не запускать. `config/r0.yaml` не править: настройки прогонов — через `--ac`.
4. Модель шага 4 — Claude Haiku (`--llm haiku`, назван явно, как в m119). Без судьи начала запросов меньше; ожидаемая цена — меньше $0,1.
5. Псевдонима `arl` в оболочке агента нет: первая строка блока определяет функцию. Блок запускать целиком.
6. Итог — «IMPLEMENTED» (патч) и «MEASURED» (замеры).

## Шаг 4. Настоящий прогон — два варианта, три источника, судья начала выключен
```bash
arl() { .venv/bin/python -m autoreels "$@"; }
cd /Users/danny/Documents/autoreels
rm -f handoff/m120/run.txt
WIDE=thesis,conclusion,example,metaphor,question,explanation,address
for S in "IMG_6848" "2026-08-08 11h 42m 49s" "Pxl 20260621 112938952"; do
  { echo "=== $S montage"; /usr/bin/time -p .venv/bin/python -m autoreels autocut "$S" --llm haiku \
      --ac lean_depth=1 --ac rhythm=true --ac context_judge=false --ac clips_every_min=3.5 \
      --out "reviews/${S}_auto_m120-montage.txt"; } 2>&1 | tee -a handoff/m120/run.txt | grep -E "^autocut|сборок: до|Claude |^real|ошибка"
  { echo "=== $S mixed"; /usr/bin/time -p .venv/bin/python -m autoreels autocut "$S" --llm haiku \
      --ac generator=mixed --ac seed_roles=$WIDE --ac target_sec=35 --ac rhythm=true --ac context_judge=false \
      --ac clips_every_min=3.5 --out "reviews/${S}_auto_m120-mixed.txt"; } 2>&1 | tee -a handoff/m120/run.txt | grep -E "^autocut|сборок: до|Claude |^real|ошибка"
done
```
Ожидается: по каждому источнику и варианту — `сборок: до N`, `autocut …: предложено сборок K …`, строка цены Claude, `real …`. Строки «модель против начала» быть не должно: судья начала выключен.
