# autoreels — заметки для агентов петли

Главный источник правил — `CLAUDE.md` в корне (Claude Code читает его сам): жёсткие инварианты 1–12,
граница ОБЛАКО/ЛОКАЛЬ, машины. Этот файл — только то, что нужно агенту петли сверх него.

## Что это
CLI: длинное talking-head видео → вертикальные рилсы 9:16 с выжженными субтитрами и заголовками.
Архитектура — `PROJECT_GUIDE.md`, ядро отбора — `R0_SPEC.md`, план и статус — `PLAN.md`.

## Команды
- `make setup` — venv `.venv` и зависимости (`.[dev]` + numpy).
- `make test` — весь юнит-слой (`pytest`, integration выключены). На Linux ~2 минуты.
- Один файл: `.venv/bin/python -m pytest tests/test_select_validate.py -q`.

## Где работает агент
Исполнитель петли на Mac владельца — в отдельной копии репозитория (`~/loop-work/…`), не в рабочей папке
владельца: там нет `.env`, исходных видео, `reviews/`, `reels-out/` и кэшей. Тесты на каждый PR ещё раз
гоняет CI в GitHub Actions (Ubuntu, ffmpeg из apt, без GPU и ключей).
- Тесты не должны требовать ключей и локальных данных (инвариант проекта: «тест на незакоммиченных
  данных — не тест»). Нужна фикстура — коммить фикстуру.
- Рендер, SSH на сервер, реальные вызовы Groq/OpenRouter — только через make-цели из раздела ниже.
  Прямой `ssh`/`scp`/`curl` агенту запрещён; `make …` разрешён.

## Локальные команды (рендер, сервер)
Пока не заведены — их описывают мозг и владелец в первом разговоре: какие цели (`make render …`,
`make server-…`), на какой сервер, откуда берутся ключи. До этого рендер и живые вызовы проверяет владелец —
в отчёте агента отдельной строкой.

## Не трогать без задачи
`manifests/`, `calibrations/`, `transcripts/`, `data/` — реальные данные владельца; тесты в них не пишут
(autouse-гвард это проверяет).
