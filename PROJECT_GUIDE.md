# Авто-Рилс — описание проекта

Инструмент автоматически режет длинное горизонтальное видео на короткие вертикальные рилсы (9:16) **без ручного монтажа**. Облако выбирает моменты и отдаёт текстовый план нарезки; локальное железо рендерит по плану.

---

## Цель и рамки (MVP)

- **Что делает:** длинное видео (~60 мин) → набор готовых вертикальных рилсов с выжженными субтитрами.
- **Для кого:** персональное использование, расширение на узкий круг — позже.
- **Тип контента MVP:** talking-head, один человек, статичен и по центру кадра. Это упрощение снимает самую дорогую часть (трекинг говорящего) — её в MVP нет.
- **Режим:** автоматический по умолчанию. **Ручной отбор — равноправный режим, не запасной путь:** на нём измерено 4% брака против 13% у автоматики, и он не зависит от лимитов провайдера.

---

## Ключевой архитектурный принцип: граница ОБЛАКО / ЛОКАЛКА

Единственный несущий концепт проекта. Конвейер физически разделён на два тира, и это разделение объясняет всё остальное (где живут лимиты, что передаётся между этапами, что бесплатно).

| | ОБЛАКО (API) | ЛОКАЛКА (железо) |
|---|---|---|
| Делает | транскрипция, оценка кандидатов | нарезка блоков, отсев, границы, кроп, субтитры, рендер |
| Инструменты | Groq (Whisper + LLM) | ffmpeg, детерминированный код |
| Стоимость | бесплатный тариф, упирается в лимиты | бесплатно по определению, лимитов нет |
| Узкое место | **OTPM на LLM-выборке** (выход, Groq free: 1000 tok/min) | скорость рендера на 8 ГБ GPU |
| На выходе | **JSON-манифест** (план), не видео | mp4-файлы рилсов |

**Видео между тирами не передаётся.** Облако работает только с текстом и звуком и отдаёт лёгкий манифест. Исходник всё время лежит локально, где и рендерится.

**Доля облака сокращается по мере развития.** Изначально LLM искала моменты, оценивала их и писала заголовки одним вызовом. Сейчас границы кандидатов находит код, мусор отсеивает код, заголовки уходят в отдельный шаг — модели остаётся один вопрос: есть ли здесь законченная мысль и стоит ли её смотреть. Этот же вопрос может ответить человек, и тогда облако в отборе не участвует вовсе.

## Поток файлов и приём исходника

### Рабочий поток (production) — всё на одной машине

Все команды гоняются на системнике Windows (там файлы, там рендер, там `GROQ_API_KEY`). Граница ОБЛАКО/ЛОКАЛКА здесь — разделение кода, а не машин.

```
СИСТЕМНИК WINDOWS (весь поток):
  1. arl c                       # калибровка кропа → calibrations/<sha>.json
  2. arl run inputs/video.mp4    # анализ → manifests/<stem>.json
  3. arl r                       # рендер → reels-out/<stem>/
```

Пункт меню «Анализ + рендер» и флаг `--render` совмещают шаги 2 и 3. В батче рендер готового манифеста идёт **фоном**, пока анализируется следующий источник: сеть и GPU перестают простаивать по очереди. Одновременно рендерится не более одного манифеста.

**Роль машины** задаётся в `config/render.local.yaml` (`role: analyze | render | both`). Машина с ролью `analyze` откажется рендерить с внятным сообщением, а не свалится в CPU-кодирование на часы.

### Каталоги

| Каталог | Что лежит | В git |
|---|---|---|
| `inputs/` | исходники, ждущие обработки | нет |
| `inputs-archive/` | обработанные исходники | нет |
| `manifests/` | манифесты — контракт между тирами | **да** |
| `calibrations/` | профили кропа по хэшу источника | **да** |
| `transcripts/` | человекочитаемые транскрипты | нет |
| `reviews/` | файлы ручной разметки | нет |
| `reels-out/` | готовые клипы | нет |
| `data/cache/` | транскрипты по хэшу аудио + параметрам | нет |
| `data/blocks_dataset/` | эталонные оценки человека | **да** |

Sidecar-файлы рядом с манифестом (`.discarded.json`, `.blocks.discarded.json`, `.blocks.topk_cut.json`, `.failed_chunks.json`) в git не идут и исключаются из обнаружения манифестов централизованно — иначе они читаются как манифесты и роняют команды.

### source-привязка в манифесте

Поле `source` = имя файла, `source_sha256` = хэш содержимого. Рендерер ищет исходник **по хэшу** в `inputs/` и `inputs-archive/` — манифест не применится к чужому файлу-тёзке, а обработанный источник остаётся рендеропригодным после архивации.

## Конвейер по стадиям

Дешёвый текстовый этап стоит первым и работает стоп-чеком: если выборка моментов плоха, рендерить нечего.

### R0 — Выбор моментов

Стадия из облачной стала смешанной. По порядку:

**1. Транскрипция** *(облако)* — Whisper large-v3, word-level таймкоды, чанкинг аудио по ≤10 мин с границами по тишине. `initial_prompt` подаётся в каждый чанк: без него на разговорном материале Whisper почти не ставит знаков препинания (1.8 против 9.2+ на 100 слов), а вся логика границ построена на пунктуации. Промпт обязан быть непродолжаемым, иначе модель дописывает его в вывод как услышанную речь.

**2. Сжатие** *(код)* — word-level → sentence-level с таймкодами, схлопывание филлеров. Примерно двукратная экономия токенов.

**3. Нарезка на блоки-кандидаты** *(код)* — границы по паузе, абзацу, смене говорящего (тире), терминальному знаку. Блок укладывается в `[min_meaningful_sec, max_duration]`: короткие сливаются, длинные режутся по внутренней самой длинной паузе. `id` блока = хэш текста, он же ключ кэша и разметки.

**4. Отсев мусора** *(код)* — артефакты Whisper (дописанные титры), оргмоменты и промо, приветствия и прощания по фразам, низкая плотность речи, зацикливание. Артефакт, приклеенный к концу блока, отрезается, а не отбрасывает блок целиком. Каждый отсев — в sidecar с причиной.

**5. Эвристический скоринг и top-K** *(код)* — признаки, считаемые без модели: длительность в сладкой зоне, терминальный знак в конце, самодостаточное начало, вопросительная арка, контринтуитивные маркеры, лексическое разнообразие; штрафы за висящие отсылки и смену говорящего внутри блока. Отбирается top-K **в пределах окна**, а не глобально, чтобы покрытие не сбилось в одно удачное место записи.

**6. Отбор** — два взаимозаменяемых пути:

- **LLM** *(облако)* — оценивает подготовленных кандидатов по рубрике `R0_SPEC` §2 и возвращает только оценки. Границы уже известны коду, заголовки делаются отдельно.
- **Человек** — `arl blocks --review` выгружает блоки, человек (или модель в любом чате) ставит оценки, `--apply` собирает манифест. Лимиты провайдера в этом пути не участвуют. Ручная склейка блоков через `+` — явная инструкция: снап может двигать только внешние границы и не имеет права резать внутри неё.

Оба пути дают одно и то же — список блоков со score; манифест отличается полем `selection_source`.

**7. Границы** *(код)* — снап начала и конца к словам, предложениям и паузам; ремонт висящего начала сдвигом к границе предложения вместо отбрасывания кандидата; обрезка длинных моментов **от начала**, не от конца (развязка живёт в конце); дедуп по перекрытию диапазонов; в интервью-режиме — обрезка перед репликой ведущего.

**Длина клипа** — конфиг, не хардкод:

| Пресет | min | max | Платформа |
|---|---|---|---|
| `shorts` (дефолт) | 15 | 90 | YouTube Shorts, универсал |
| `reels` | 15 | 90 | Instagram Reels |
| `tiktok` | 15 | 180 | TikTok |

Площадки допускают до 3 минут, но вовлечённость падает раньше, и Instagram не рекомендует Reels длиннее 3 минут новой аудитории — 90 с рабочий потолок.

**Стоп-чек:** моменты осмысленные и самодостаточные в пределах лимита? Если нет — дальше не идём.

### R1 — Детерминированная нарезка *(локалка)*
ffmpeg режет по границам слов → фикс-кроп 9:16 → сырой вертикальный mp4.

### R2 — Оркестрация + review + выдача
FastAPI-сервис + очередь. Review-экран: превью клипа, inline-правка таймкодов, per-clip approval. Approve → mp4 уходят в SMM кросс-постер. **Незакрытый пункт.** Ручной отбор на уровне блоков (R0, шаг 6) закрывает часть этой потребности раньше и дешевле: текст читается быстрее, чем смотрится видео, и рендерится только выбранное.

### R3 — Субтитры *(локалка, на практике must)*
Word-level → ASS-шаблон → ffmpeg выжигает. Смотрят без звука — поэтому фактически часть MVP.

### R4 — Границы по смыслу *(полировка)*
Snap начала и конца к паузам, словам и предложениям. Реализовано и замерено; см. R0 шаг 7.

## Манифест — формат «проекта»

Граница между тирами. Лёгкий JSON:

```json
{
  "source": "lecture_2026.mp4",
  "source_sha256": "f930ebd518…",
  "source_kind": "lecture",
  "duration_preset": "shorts",
  "selection_source": "human",
  "transcript_params_key": "84b62c5276da",
  "reels": [
    {
      "id": "r01",
      "start": 124.3,
      "end": 168.9,
      "r0_start": 126.0,
      "r0_end": 167.2,
      "end_drift_sec": 1.7,
      "end_snap_reason": "sentence",
      "start_snap_reason": "repaired_to_sentence",
      "rank": 1,
      "score": 87,
      "hook": "первая фраза-зацепка",
      "title": "виральный заголовок клипа",
      "description": "готовый текст публикации",
      "flags": [],
      "crop": { "x": 980, "y": 220, "w": 1010, "h": 1795 },
      "subtitles": [ { "word": "привет", "t0": 124.3, "t1": 124.6 } ]
    }
  ]
}
```

Поля, которые стоит понимать:

- **`r0_start` / `r0_end`** — границы, названные моделью. Финальные `start`/`end` ставит код. Разница между ними, `end_drift_sec`, есть **автоматическая мера брака**: клип, чей конец уехал далеко за смысловую границу, заканчивается посреди следующей мысли. Это избавляет от необходимости размечать вручную для мониторинга.
- **`end_snap_reason` / `start_snap_reason`** — чем именно определена граница (`sentence`, `pause`, `before_host_turn`, `no_punctuation`, `repaired_to_sentence`…). Причина обязана соответствовать действительности: «sentence» ставится только когда терминальный знак реально выбран.
- **`transcript_params_key`** — отпечаток транскрипта (модель, провайдер, хэш промпта), на котором собран манифест. Без него `diagnose-cuts` и `resnap` могут взять другой транскрипт того же аудио и посчитать — или записать — неверные границы.
- **`selection_source`** — `human` или пусто. Отличает ручной отбор от автоматического.
- **`segments`** — явный список `[{start, end}]` окон воспроизведения внутри тела клипа (пустой список = одно окно `[start, end]`). Используется для клипов с вырезанными филлерами: рендерер конкатенирует только сегменты и выбрасывает разрывы между ними.
- **`cold_open`** — хук-окно `{start, end}`, которое воспроизводится **перед** телом клипа (replay hook). Задаётся ревьюером через `h:N`, где N — номер предложения в блоке. Добавляет к длительности, а не заменяет тело.
- **`speed`** — коэффициент ускорения воспроизведения (1.0 = норма, >1 = быстрее). Применяется ко всему клипу при рендере через `setpts`/`atempo`. Ставится ревьюером как `@1.15`.
- **`title_overlay`** — текст заголовочной плашки (`t:` из ревью), выжигается поверх кадра. Пустой на автоматическом пути.
- **`tail_last_word_end`** / **`tail_next_word_start`** — таймкоды последнего услышанного слова и (если есть) слова, втянутого в хвостовой падинг. Используются рендерером для точного `afade` — заглушить именно втянутое слово, а не весь хвост фиксированным фейдом. Значения `None` = нет данных (легаси-манифест), рендер падает на конфиг-фейд.

**Иммутабельность.** После сборки манифест не меняется: это снимает git-конфликты между машинами и делает результат воспроизводимым. Отсев кандидатов пишется в sidecar рядом, а не внутрь.

**Опциональный выход:** fcpxml → DaVinci Resolve для ручной доводки тех 10% клипов, где хочется цвет или тонкую анимацию титров.

## Визуальная часть (под talking-head, статичная камера)

- **Кроп — фиксированный прямоугольник `{x, y, w, h}` в пикселях исходника.** Камера и человек статичны → рамка калибруется один раз на сетап и покрывает всё видео. Калибровка учитывает rotation-метаданные: кроп валидируется в **отображаемом** пространстве кадра, иначе на повёрнутых записях рамка уезжает.
- **Трекинг / active-speaker detection:** не нужны.
- **Субтитры:** ASS-шаблон, настраивается один раз.
- **Frame-grid alignment.** Каждое окно воспроизведения выравнивается по сетке кадров исходника (1/fps) до сборки фильтра. Без этого конкатенация сегментов с дробными границами даёт рассинхрон аудио и видео на стыках. Выравнивание выполняется в `_snap_windows_to_frames` в `local/render.py`; параметр сетки — `r_frame_rate` из источника.

### Хвостовой аудиофейд (trailing air)

После последнего слова клипа рендерер добавляет тишину (`tail_pad_sec`) и плавно заглушает её через `afade`. Если в это окно тишины попало слово из следующей мысли (втянутое в падинг), фейд начинается раньше — прямо от конца последнего нужного слова — так что слушатель его не слышит. Точка начала фейда берётся из `tail_last_word_end` / `tail_next_word_start` манифеста (записываются при `--apply`). Значения конфига — в `config/render.local.yaml`.

### ASS-стиль субтитров
Белый, жирный, CAPS, по центру, нижняя треть; тонкий контур + лёгкая тень; без подложки. Поп-ап по словам через `\k`, 2–4 слова в строке.
```
Style: Pop,Montserrat,72,&H00FFFFFF,&H00FFFFFF,&H00000000,&H64000000,-1,0,0,0,100,100,0,0,1,3,2,2,40,40,300,1
```
`MarginV ≈ 300` сажает текст в нижнюю треть, выше зоны UI платформы.

## Технологии

| Узел | Решение | Примечание |
|---|---|---|
| Транскрипция | Groq Whisper large-v3 (API) | word-level; отдельный пул лимитов, в OTPM не упирается |
| LLM-выборка | Groq (см. `config/r0.yaml` + `arl models`) | несущий лимит OTPM 1000 tok/min |
| Provider-абстракция | Groq → OpenRouter failover | пинг настроенных моделей на старте |
| Предотбор кандидатов | детерминированный код | блоки, отсев, эвристика, top-K |
| Ручной отбор | `arl blocks --review/--apply` | verbose для редактора, compact для чата |
| Нарезка/кроп/рендер | ffmpeg (локально) | Mac: hevc_videotoolbox + libass; Windows: hevc_amf/h264_amf |
| Субтитры | ASS + ffmpeg burn-in | |
| Оркестрация | FastAPI + очередь | не начата |
| Review UI | React | не начат |

**Имена моделей протухают молча** — у Groq и у OpenRouter. Наличие модели в каталоге OpenRouter не означает доступность: часть бесплатных отдаётся только по своему ключу провайдера. `arl models` показывает живые списки и пингует настроенные, возвращая ненулевой код при проблеме.

## Жёсткие правила и принципы

- **Determinism-first.** LLM только ранжирует и предлагает. Финальные границы реза выставляет детерминированный код. Скоры — подсказка для сортировки, не источник истины.
- **Человек равноправен модели.** Ручной отбор — не аварийный путь, а второй вход в ту же точку конвейера. Ручная склейка блоков — инструкция, которую последующие стадии обязаны уважать.
- **Пустой массив — валидный результат.** «Хороших моментов не найдено» — ожидаемый исход для скучного видео. Но **нулевой урожай при непустом транскрипте — не успех:** источник не архивируется и попадает в сводку отдельной категорией.
- **Two-phase.** Phase 1 гонит автоматически до `awaiting_review`. Phase 2 (финальный рендер) — по approve.
- **Token-aware на R0.** Несущий лимит — OTPM (выход); правится `max_output_tokens`, не размером чанка. Урожай определяется числом запросов. Подробно — `docs/audit-groq-413.md`.
- **Чек-флаги детерминированы** и считаются от **финальных** границ, а не от сырых: проверка, стоящая до преобразования, которое её обесценивает, — повторяющийся класс багов в этом проекте.
- **Кэш ключуется по всем входам, влияющим на результат.** Транскрипт — по хэшу аудио **и** параметрам транскрипции. Иначе смена промпта не инвалидирует кэш, и «новый» результат оказывается старым.
- **Отчёт не доказательство.** Заявленные улучшения проверяются по файлам на диске, а не по сводке: за время работы дважды цифры из отчёта не подтверждались содержимым `manifests/` и `transcripts/`.

## На горизонте (вне MVP)

- Рефрейминг с трекингом говорящего (для контента, где человек двигается).
- Zoom-эффект.
- Текстовый контент-пайплайн на полных транскриптах.
- Масштабирование на 3–5 пользователей.
- Локальный LLM для R0 (при GPU ≥16 ГБ или на CPU с 32 ГБ ОЗУ) — снимает лимиты полностью. Отбор моментов не интерактивен, поэтому низкая скорость может оказаться приемлемой платой за отсутствие квот.
