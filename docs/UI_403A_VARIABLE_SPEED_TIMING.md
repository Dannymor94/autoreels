# UI-403A — variable-speed timing contract and FFmpeg experiment

The existing production renderer applies one Reel.speed after concat; preview, subtitles, FX, music, tail and duration checks assume that contract. Do not write per-window rate metadata into production manifests until every consumer is ready. This opt-in slice compiles an ordered vector of rates (0.5–2.0) against source-time playback windows into immutable output intervals. Repeated source occurrences remain distinct. The existing subtitle remapper has an explicit per-window mode using the same mapping; legacy calls are unchanged. Hard cuts only: reject simultaneous global speed, crossfade, invalid bounds/rates or cues crossing a retimed boundary. A direct synthetic FFmpeg experiment retimes both video and audio before concat, checks duration, A/V sync and tone pitch/order. It is not the production FFmpeg pipeline. Next: manifest schema with backward compatibility and no old digest churn; exact revision binding; renderer opt-in limited to simple hard cuts, frame/sample snapping, shared preview mapping; then UI persistence, effects/seams and device acceptance. No owner media, deployment, dependency, GPU or paid API.
