# Render targets R4 — одно приложение, три места исполнения

2026-11-27. BASE main a23bce31d713f07299fee06ce175f14745126d54. Уточнение владельца: «gamebox — это пример удаленного арендованного сервера ... отрендерить как на Мак (то есть на ПК собственника) или прямо на мобильном телефоне». Документация/продуктовый контракт, не разрешение на реальный рендер, сеть, аренду, новый пакет или передачу видео.

## 1. Продукт
Редактор/устройство управления не равны месту исполнения. Телефон может управлять Mac или удалённым узлом либо рендерить самостоятельно. Mac может рендерить без gamebox. Remote — конкретный доверенный узел, свой или арендованный, с локальным для него media workspace; gamebox только один экземпляр. UI-105 (#42 merged, #43 synthetic deployment) опциональный транспорт доступа к узлу, не центральный обязательный backend. Не отменять уже согласованный синтетический пилот; не расширять его scope. iOS и Android — целевые платформы, их готовность не заявляется. Windows/Linux desktop — переносимость контракта, не доказанная готовность всех сборок.

## 2. Один смысловой план, несколько исполнителей
Сохраняем существующий Pydantic Manifest, planner, детерминированные правила и ручной приоритет. Не создавать альтернативный выбор фрагментов, второй авторитетный timeline или независимую историю проекта. Спецификация RenderPlan должна описывать effective ordered windows, rational/tick time, source/media/asset/font hashes, crop, subtitle cues, visual/audio layers, codec/output profile, version and provenance. Не менять существующую схему/CLI и run_key без отдельного миграционного решения. Исполнители получают проверенный immutable plan, выбирают только разрешённый технический encoder/backend. FFmpeg существующий reference для desktop/remote. Для mobile допускается адаптер native SDK или переносимое исполнение только после измерений и проверки соответствия. Неподдерживаемая операция = явный unsupported/blocked, не тихое упрощение/передача в сеть. Равный смысл, тайминг, слой и экспортный профиль не означают побайтово одинаковые MP4 при разных аппаратных кодерах; качество швов, subtitle placement, A/V sync и full decode обязательны. Сохранить atomic output, errors, exact artifact reviews.

## 3. Контракт до UI-201 (proposal, без кода)
- RenderTarget: stable target_id, kind desktop|remote|mobile, platform, capabilities, availability, trust/authorization and version. Не жёсткий hostname, SSH command или path. Выбор explicit; предложенный auto target только после согласованной политики.
- RenderRequest: project/revision, immutable plan_ref/hash, asset refs/hash, target_id, requested profile, idempotency key. Readiness: assets available/verified at target; unsupported effect/codec; storage/limits; permission and estimated transfer where applicable. Никаких произвольных команд от UI.
- Job: target-specific execution, progress/stage, cancel, bounded resources, retries and recovery with lease/idempotency; state source authoritative, no duplicate render into same destination. Distinct states missing-assets / unavailable / unsupported / failed; no auto-switch to remote. Local storage stays usable disconnected.
- Artifact: exact content SHA, plan hash, target_id, effective encoder and versions, location ref (not client-supplied path), validation, revision. Export and review decisions not automatically shared across different renders. Explicit sync/import of project revisions/artifacts only; conflict and missing assets fail closed. No mandatory central project DB or server for standalone local mode; multi-node replication protocol separate scoped design.

## 4. Data boundaries
AI semantic tier accepts existing approved text/ASR workflow; no video to LLM/video APIs. Media tier is where actual bytes live, can be user's PC, phone or explicitly trusted remote worker. If source already on chosen device, no media transfer. Moving data between devices requires explicit user approval of destination, files, volume and retention; protected transport and verification by hash. No public media, silent upload, implicit provider fees, source deletion, new default cloud rendering. R4 changes geographical assumption, not AI privacy or security gate. Real rented server deployment requires separate HIGH provisioning/security/data handling and cost GO. No rented server purchase now.

## 5. Mobile technology candidates, not selection
Native iOS AVFoundation/VideoToolbox and Android Media3 Transformer/MediaCodec are candidates for hardware-assisted execution. Browser WebCodecs + compositor/muxer and ffmpeg.wasm are candidates for limited portable mode, but support, codec and memory/background constraints vary. A browser remotely playing a server render is not local phone rendering. Need standalone mobile path with source/plan/fonts/assets available on device, no mandatory PC or remote worker; offline manual render once assets/plan present, semantic AI optional and separately constrained. No promise of full feature parity or 4K/background render before tests. Native adapters may reuse shared core/build assets rather than invent second editor. Compare minimal synthetic clip with current FFmpeg reference: crop/trim, audio, burned Russian subtitles, 9:16 MP4 H.264/AAC target, validate duration/timing, decoded frames, file integrity, memory, thermals, runtime, battery, cancellation/interruption/recovery. Test physical iOS/Android; pick first platform using owner's device and measurements. Check licensing/fonts/codecs/SDK distribution before adopting dependencies.

## 6. Queue changes
R4 design before UI-201, no rewrite of merged UI-101–105. UI-201: versioned capability and target selection contract (mock first); UI-202: job coordinator with fake targets and no fallback; UI-203: preserve effective config and manual decisions; UI-204: reuse Mac/remote CLI adapters, explicit target and source placement, synthetic only until GO. Separate MOBILE-SPIKE: prove local render on actual phone using synthetic fixtures, select engine, no dependency adoption before approval. Then MOBILE-WORKER: implement supported subset, common plan semantics/validation, explicit unavailable capabilities. UI-401/404 preview/render adapters use selected node; UI-105 test phone as remote controller independently of native render proof. Deployment of additional nodes not necessary for localhost feature development. Test minimal contract/parity per backend; HIGH privacy/security for transfers and remote connections, targeted independent QA only for concrete risk. Owner accepts real results. No estimates or capability claims without measurements.

## 7. Open decisions
Mobile first platform and browser/native tradeoff after spike/device availability. Remote workspace/transfer policy requires explicit owner decision before real files move; automatic target selection and renting/billing not authorized. All three target modes are product requirements, not mutually exclusive options.
