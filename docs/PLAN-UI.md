# PLAN-UI — план реализации интерфейса (R2)

Правила и контракты — в `UI-HANDOFF.md`. Здесь только порядок работ.

Каждый этап устроен одинаково:
- одна задача агенту ветки UI;
- результат, который владелец трогает руками;
- гейт: владелец смотрит вживую и говорит «принято» или что неудобно;
- только потом следующий этап.

Задачи для основной ветки (MU) идут отдельно, их делает агент `~/Documents/autoreels`, и вставляются в его очередь между M1.8 и M1.9 так, чтобы не задерживать UI.

Обозначения: **U** — этап ветки UI, **MU** — задача в основной ветке для UI, **В** — решение владельца.

---

## Карта этапов

| этап | что владелец получает | нужно от основной ветки | гейт |
|---|---|---|---|

| U1 | каркас: сервер, экран, демо-источник | — | демо-клипы играют с перемоткой в Safari и Chrome |
| U2 | просмотр своих клипов вместо QuickTime | — | владелец смотрит лекцию в UI |
| U3 | вердикты клавишами, файл для агента | MU1 | один источник пройден в UI, агент отработал по файлу |
| — | **слияние в `main`** | — | `pytest` основной ветки зелёный, UI запускается из `~/Documents/autoreels` |
| U4 | варианты рядом, выбор лучшего | — | сравнение montage / m18_synth сделано в UI |
| U5 | «входящие» и задания, проверочный рендер | MU2 | рендер запущен из UI, статус и результат пришли сами |
| U6 | текст клипа рядом с видео | MU3 | клик по слову перематывает, текущее слово подсвечено |
| U7 | ручная подрезка по словам, проверки, подсказки | MU4 | клип подрезан в UI, применён, отрендерен без правок руками в файлах |

## Этапы ветки UI

### U0 — подготовка (владелец, ~15 минут)
- `cd ~/Documents/autoreels && git worktree add ../autoreels-ui -b ui`
- `brew install node` (В1)
- Положить `UI-HANDOFF.md` и `PLAN-UI.md` в `autoreels-ui/docs/`.

### U1 — каркас
- `src/autoreels/orchestr/`: приложение FastAPI, `pipeline_gateway.py` (переходник, запасной `capabilities`), настройка `AUTOREELS_ROOT`, раздача видео с HTTP Range и защитой путей, точка запуска `python -m autoreels.orchestr`.
- `ui/`: Vite + React + TypeScript, TanStack Query, тема на CSS-переменных, одна пустая страница со списком источников.
- Генерация типов: скрипт OpenAPI → `ui/src/api/types.gen.ts`, тест «типы не устарели».
- `demo/`: скрипт, который строит демо-источник — 15–20 с, сгенерированная речь, манифест, 3 клипа, один проверочный вариант. Результат кладётся в git, чтобы тесты не зависели от `say`.
- `ui/README-AGENT.md` с первыми рецептами.
- **Спайк JASSUB:** собрать с шрифтами рендера и показать один `.ass` поверх видео. Результат — да или нет, в отчёт.
- Тесты: pytest на API (Range, выход за корень запрещён, список источников), Vitest на одной компоненте.
- **Гейт:** `python -m autoreels.orchestr` открывает демо, клипы играют и перематываются в Safari и Chrome.

### U2 — просмотр
- Источники и клипы из `AUTOREELS_ROOT/reels-out/<stem>/` и `_gate/<имя>/`, только чтение.
- Вертикальный плеер. Вкладки вариантов с переключением на той же секунде. Клавиши: пробел, ←/→ на 2 с, J/K к соседнему клипу, `?` показывает подсказку.
- Лёгкие H.264-копии как задание в фоне, хранятся в `data/cache/ui/`. Пока копии нет, Safari играет оригинал.
- Запоминается, где владелец остановился.
- **Гейт:** владелец смотрит клипы лекции в UI вместо QuickTime.

### U3 — вердикты
- Формат из `UI-HANDOFF.md` §5: `render_ref {fp, mp4}`, метки, `choose`, `gate`.
- Метки на клавишах 1–9. Enter означает «ок» и переход к следующему клипу. Засечки на шкале. Комментарий к моменту.
- Статусы клипов в списке: принят, замечания, не смотрел, перерендерен и ждёт пересмотра. Устаревшие вердикты определяются по `render_ref.mp4`.
- Запись атомарная, в `AUTOREELS_ROOT/reviews/verdicts/<stem>.jsonl`.
- Закрытие гейта кнопкой.
- **Гейт:** владелец прошёл один источник целиком в UI. Агент основной ветки по файлу вердиктов исправил и отрендерил без пересказа в чате.
- **Затем слияние в `main`.**

### U4 — сравнение вариантов
- 2–3 плеера рядом, синхронный запуск, пауза и перемотка. Запись `choose` с `refs`.
- После перерендера по замечанию клип открывается в режиме «было / стало».

### U5 — «входящие» и задания
- Модель задания: id, тип, статус, прогресс, лог, результат. Задания хранятся в `data/jobs/`, прогресс приходит в браузер через SSE.
- Проверочный рендер клипа или фрагмента ±3 с в `_gate/<имя>/` командой из `AUTOREELS_ROOT`, с учётом `.render.lock`.
- Главный экран «входящие»: перерендеренное, ждущее просмотра, упавшее, отданное агенту.
- Обновление экрана по изменениям на диске (`watchfiles`).

### U6 — текст клипа
- Текст рядом с видео: вошедшее, вырезанное, такты, границы, строка разметки снизу. Данные — из `--dry-run --json`.
- Клик по слову перематывает. При воспроизведении текущее слово подсвечивается.
- Клавиша «к тексту» открывает текст на текущем слове.

### U7 — ручная подрезка
- Команды: начало, конец, вырезать, хук, крупный, ключевое слово, такты. Клик по словам, точная подгонка по волне (wavesurfer.js) с шагом в кадр и привязкой к паузам.
- Журнал правок `reviews/edits/<stem>.jsonl` с автором и базовой версией. Отмена любого шага. Перед применением показывается разница.
- Применение через `--apply --install` с резервной копией файла ответа.
- Проверки на лету (предупреждения в тексте) и подсказки-исправления одним кликом — всё считает сервер.

### U8 — черновой просмотр
- H.264-копия исходника с частыми ключевыми кадрами. Плеер перескакивает по окнам манифеста двумя `<video>` попеременно.
- Субтитры через JASSUB, если спайк в U1 прошёл, иначе HTML с пометкой «приблизительно». Подпись «черновик».

### U9 — субтитры
- Правка текста фразы как поправка к слову. Пресеты стилей на источник и на клип, с переопределением полей. Проверочный рендер 5 с.

### U10 — заставка и концовка
- Библиотека роликов: приведение к формату при добавлении, ссылка по хешу. Выбор на источник и на клип. Порядок: заставка → клип → хвост → концовка.

### U11 — эффекты
- Ручки строятся по каталогу из `capabilities`. Первый эффект — наплыв.

## Задачи основной ветки для UI (MU)

| # | задача | нужна к |
|---|---|---|
| MU1 | `render.json`: версия кода (git sha) и хеш настроек. Отпечаток учитывает всё, что влияет на картинку: планы, `close_intervals`, искусственный хвост. Проверить стабильность номеров `r*` после повторного `--apply`, если нестабильны — `clip_uid`. | U3 |
| MU2 | машиночитаемый статус рендера (`--json`: прогресс, ошибка, путь); рендер фрагмента по времени; алиас `arl ui` | U5 |
| MU3 | `--apply --dry-run --json`: первые и последние слова, такты, холодный старт, планы, выделения, предупреждения, длительность, **карта времени клип → исходник**, пословные метки времени; `schema_version` в манифесте и во всех `--json` | U6 |
| MU4 | границы клипа с точностью до слова или времени в грамматике; проверки разметки (конец на слове-паразите, начало без контекста, граница без паузы, лимит длины) в выводе MU3 | U7 |
| MU5 | `arl capabilities --json`: ключи разметки, метки, эффекты с параметрами, пресеты, схема настроек | U9, U11 |
| MU6 | поправки субтитров по словам в манифесте; пресеты стилей субтитров | U9 |
| MU7 | заставка и концовка в манифесте и рендере; правило «концовка вместо ухода в чёрное» | U10 |
| MU8 | каталог эффектов в рендере; наплыв переезжает в него | U11 |

Снимки JSON-схем всех `--json`-выводов кладутся в тесты основной ветки сразу в MU1–MU3, чтобы изменение контракта падало там, где его сделали.

## Как идём

1. Владелец делает U0 и решения В1–В2.
2. Чат UI пишет задачу U1 в постоянном формате. Агент в `autoreels-ui` выполняет, отчёт «IMPLEMENTED, GATE PENDING».
3. Чат UI сверяет отчёт с кодом. Владелец проходит гейт вживую.
4. Следующий этап. Задачи MU передаются в основную ветку заранее, за этап до того, как они понадобятся.
