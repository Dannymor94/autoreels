# UI-202B — internal execution contract

An offline, internal contract for future real adapters. No launcher, API, UI, production DB, media, provider, process or network changes. Synthetic UI-202A remains as-is. The ledger table is only instantiated in isolated test DBs. Integrate with the authoritative job store when UI-204 gains a real adapter; do not introduce a mandatory central server or a second live job authority.

Immutable request binds an opaque job ID, explicit target ID/kind, plan/config digests and trusted output reservation key. The caller must compute these from the approved immutable plan and canonical destination, not accept a client path or unverified digest. Same request ID is idempotent; conflicting payload fails. One active reservation per (target_id, output_key) in one authoritative SQLite DB. This is not a cross-device/file lock; aliases, concurrent legacy CLI and actual process ownership are adapter responsibilities. No hidden target switch.

Coordinator-only clock, bounded lease, increasing fence on claim, revision CAS in one transaction. Expiry enters reconcile, retaining reservation. No automatic replay. Only a trusted adapter/coordinator with proof of process exit, reconciled staging/output and appropriate external lock may finish or reconcile. Successful outcome requires validated artifact digest. If cancel requested, no successful completion; reservation remains until confirmed stopped. Recovery may retry once (two attempts total), same immutable target; otherwise terminal failure. Exact digest acceptance on recovery is a caller responsibility. No claim of external process death, actual file validation, distributed auth, filesystem fencing, or wall-clock rollback handling yet. Coordinator clock must be nondecreasing; real adapter must fail closed on clock uncertainty. The actual output lock must cover process and promotion, including expired worker, before any real run.

QA scope: state/revision/fence rejection, bound identity, output reservation, restart via reopened SQLite, cancellation, bounded retry and reconciliation. No browser change or independent audit needed for this isolated contract; real executor integration is separately HIGH where media or new trust boundary is involved.
