# M1.9 «Карта интонации»

Статус: **запланировано**, старт — после приёмки пилота IMG_6848 (M1.7/M1.8).
Принцип: сначала замер на разметках владельца, потом внедрение. Интонация даёт подсказки и признаки, решения не принимает.

## Зачем

Сейчас программа понимает речь по тексту Whisper и по громкости (карта речи M1.8). Интонация — третий источник: тон голоса, ударение, темп, паузы. Она закрывает классы брака и ручной работы, которые текст не видит:

| проблема сейчас | что даёт интонация |
|---|---|
| «Не договорил», «мысль не закончена»: Whisper ставит точку посреди мысли или не ставит в конце | конец утверждения слышен: тон падает, затем пауза; «→ продолжение» — тон не упал, пауза короткая |
| ключевые слова `k:` и крупный план `c:` владелец ищет глазами по тексту | ударные слова (громче / выше / медленнее относительно самого спикера) — кандидаты для `k:`; «припечатанная» фраза — кандидат для `c:` |
| модель оценивает блоки только по тексту | признаки «пиковых», эмоциональных фраз — для крючка, холодного старта и финала |
| в интервью вопрос ведущего не отличается от риторического вопроса гостя (IMG: найдено 4 вопроса из многих) | вопрос и утверждение интонационно различаются; смена голоса — признак смены говорящего |

## Что строим

**Карта интонации** — расширение карты речи, на той же сетке кадров по 10 мс, с кэшем и версией (`PROSODY_VERSION`):

- тон (F0) по кадрам, нормированный **относительно спикера** (полутона от его медианы), с признаком «голос / не голос»;
- громкость (уже есть в карте речи);
- по каждому слову: средний и пиковый тон, громкость, длительность относительно средней для спикера → **ударность слова** (одно число);
- по каждому предложению: наклон тона на последних ~300 мс и длина паузы после → **«↘ конец» / «→ продолжение»**; рост тона в конце → признак вопроса;
- по блоку: «пиковость» (самые ударные фразы) — признак для оценки.

Инструменты: `parselmouth` (Praat) или `librosa.pyin`, локально, бесплатно. Аудио не меняется.

## Этапы

### A. Замер (без изменений конвейера)
1. Построить карту интонации для лекции 11h 42m, PXL_20260729 и IMG_6848.
2. Проверить на решениях владельца:
   - слова из `k:` ударнее остальных слов тех же предложений? (доля случаев, средняя разница);
   - концы `e:` владельца приходятся на «↘ конец» чаще, чем случайные концы предложений?
   - клипы с вердиктом «не договорил» / «мысль не закончена» кончались на «→ продолжение»?
   - вопросы ведущего в интервью отличаются от риторических вопросов гостя?
3. Отчёт: по каждому вопросу — число, выборка, вывод «есть связь / нет».
**Гейт A:** внедряем только то, где связь есть. Где связи нет — этап закрывается без кода.

**Замер A (M99, 2026-10-19)** — `handoff/m99/m99_intonation.py`, только чтение: 66 клипов ручной разметки семи источников, карта интонации M2.2 (`transcripts/<источник>.prosody.json`, конец тона в диапазоне спикера).
1. **Концы клипов владельца — связь есть.** «↘ конец» у 62 из 65 концов (95 %) против 390 из 484 концов фраз внутри тех же клипов (81 %); «→ продолжение» — 1 из 65 (1,5 %) против 45 из 484 (9,3 %): при случайном выборе ждали бы ~6, вышел 1.
2. **Слова `k:` — связь по растяжке, не по тону.** Слово `k:` длиннее на букву остальных слов фразы в 106 из 131 фраз (81 %); строже — только содержательные слова (≥ 5 букв) и без последнего слова фразы (оно растянуто и так; 40 % слов `k:` стоят последними): 44 из 68 (65 % против ~50 % случайно). Конец тона слова `k:` выше остальных — 37 из 68 (54 %): связи нет.
3. Вердиктов «не договорил» (`reviews/verdicts.jsonl`, M82) ещё нет; вопросы ведущего не мерились.
**Гейт A — решение владельца.** По замеру кандидаты на внедрение: этап C (клип не кончается на «→») и в этапе D — растяжка слова как признак для `k:` (тон конца слова — нет).

### B. Подсказки в выгрузке для разметки (первое внедрение, без риска)
- у предложения: `↘` (мысль закончена) или `→` (продолжается), как сейчас `⏸` и `…→`;
- в предложении: отметка 1–2 самых ударных слов (например, `*слово*`);
- решение остаётся за владельцем; цель — быстрее и точнее размечать.
**Гейт B:** владелец размечает один источник с подсказками и оценивает, помогли ли.

### C. Правило концовки
- клип не заканчивается на предложении с `→`, даже если Whisper поставил точку (как сейчас нельзя кончать на `…→`);
- явный `e:` владельца не двигается — только предупреждение;
- проверка в `verify`: конец клипа = `↘`.
**Гейт C:** на 16 эталонных клипах + IMG ни один принятый конец не сломан; на клипах с вердиктом «не договорил» правило срабатывает.

### D. Подсказки для `k:` и `c:` в автоматическом пути
- автоматический путь (без разметки владельца) берёт `k:` из ударных слов, `c:` — на самой ударной фразе;
- в ручном пути — только подсказки (этап B).

### E. Признаки для оценки блоков и для интервью
- «пиковость» блока — дополнительный признак к оценке моделью (сравнить AUC с признаком и без на чистых данных; внедрять, только если растёт);
- вопрос / не вопрос и смена голоса — дополнительный сигнал детектору реплик ведущего (замерить на IMG и PXL: найдено / пропущено / ложные).

## Зависимости
- карта речи M1.8 (кадры, слова по карте, удаление задвоенных слов Whisper);
- единая нумерация предложений в выгрузке и при применении (исправляется в пилоте IMG);
- эталон и `verify` — для гейта C.

## Чего не делаем
- не меняем звук (никакого сдвига тона и растяжения голоса);
- не вводим общие пороги «для всех» — всё относительно конкретного спикера;
- не даём интонации решать за владельца в ручном пути;
- не внедряем ничего, что не прошло замер этапа A.

## Риски
- у разных спикеров разная манера: нормировка по спикеру обязательна; в интервью — по каждому голосу отдельно;
- шум и музыка мешают определению тона: признаки с низкой уверенностью не используются;
- монотонная речь даёт слабые различия — подсказки там будут редкими, и это нормально.
