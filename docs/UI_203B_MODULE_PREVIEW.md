# UI-203B — read-only module panel

GET /api/module-settings projects six existing configured module values using the same guarded CLI config paths/loaders as UI-201B. Optional enum on/off per known module creates a temporary proposal; omission inherits the configured value. The response includes baseline and proposed values, versioned subset baseline digest, advisory invalidation and separate availability. No target is registered, so runtime availability and apply_enabled remain false. Missing/invalid/blocked config returns an empty panel, never fabricated defaults. Full YAML, secrets, paths and custom names are not returned.

Mobile panel on Export shows the configured baseline and independent draft options (inherit/on/off), explains proposal vs output semantics, displays server-calculated affected stages and resets the draft. Preview is not an applied preset, project/clip inheritance, proof of adapter readiness, nor an accepted-edit validation. No saved changes; no process, media read, rendering, network, provider, new dependency or write API. Project/clip persistence must bind to actual revision/identity; manual operation store and actual dependencies are integrated in later phases. No actual output or CLI flags changed. QA: two focused API tests with real config + local overlay, no writes, missing/invalid/symlink, auth coverage; existing schema/types/browser smoke with toggle/preview/reset. No independent audit for this read-only scope.
