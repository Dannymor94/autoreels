# UI-203A — immutable preset policy

A pure internal subset, not wired to API, live project storage, CLI, renderer or jobs. Existing behavior unchanged. Six real configured switches are projected by pipeline_gateway from already validated R0/RenderConfig objects: hook rescue (autocut.hook_clauses_autocut), montage filler cut (montage.filler_cut), two-shot, loudnorm, denoise, music. These are configured values, not runtime availability or full effective configuration; flags/manifest dependencies and actual adapter support are separate. Do not equate montage filler_cut with harmless proposal-only generation. Other switches are added only after mapping the actual stage/semantics.

Availability belongs to trusted runtime capabilities, visibility is presentation only, automation and output are distinct where implemented. Unsupported dimensions are rejected, not represented by fake toggles. ProjectPreset pins an immutable snapshot of the global values; project and clip overrides apply in that order. None inherits, explicit false disables; no mutable global pointer. Save/load integration and revision CAS are later work, not claimed by this pure object. The deterministic versioned module-options digest excludes visibility; not the full execution config_sha256. Empty overrides give exact value/digest parity. No change to existing run_key, Manifest, accepted operations or config files.

Preview lists changes and advisory invalidation stages. Visibility invalidates nothing; hook proposal switch invalidates future proposals, not accepted edits or existing render; filler cut invalidates plan and render; render switches invalidate render. Changes to unsupported modules or output affecting accepted manual/auto operations are blocked; accepted-output module protection must be supplied by trusted revision/operation store (UI-301+), no automatic removal. No apply/commit endpoint. Actual render readiness and full effective job fingerprint require UI-204/301 integration. No cost, media, dependency, execution, network or deployment.

Tests: existing CLI configuration parity, frozen snapshot/precedence, explicit false/inheritance, visibility/automation independence, no-op parity, diff/protection and rejection.
