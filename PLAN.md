Инкрементальный, каждый milestone даёт реальный выход до начала следующего. Стоп-чеки явные.

## Решение: архитектура масштабирования отложена

Полноценная архитектура масштабирования **НЕ строится** до закрытия M1. Швы под масштаб заложены (граница облако/локаль, провайдер-абстракции, манифест-контракт, идемпотентность). Узкие места определяются на работающем конвейере с реальной пачкой видео, **не заранее**.

## M1 — Полный R0 + качество отбора ✅ В ОСНОВНОМ ЗАКРЫТ

Сделано:

- **R0 recall** — over-generation с `candidate_multiplier`, ранжирование по score, top-N через `max_reels`, отсев в `<манифест>.discarded.json`.
- **Whisper-чанкинг** — аудио по ≤10 мин с VAD-границами, склейка word-таймкодов со смещением, укладка в лимит Groq 25 МБ.
- **R0-чанкинг** — токенный чанкинг транскрипта, overlap, дедуп по перекрытию диапазонов.
- **OpenRouter failover** — провайдер-пул с adaptive-стратегией, пинг-проверка на старте, исключение недоступных провайдеров с внятной причиной.
- **Кликбейт `title` + `description`** — рамка R0_SPEC §4 + few-shot.
- **R4 — snap границ** — притяжка к паузам и словам, punctuation-first снап конца.

Осталось в M1:

- **R2 — оркестрация + review-UI.** FastAPI + очередь + статусная модель (`awaiting_review`). React-экран: превью клипа, правка in/out, правка заголовка, approve/reject. Скилл `frontend-design`. **Это главный незакрытый пункт M1.**

## M1.5 — Качество клипов по смыслу ✅ ЗАКРЫТ

Отработка жалобы «много нарезок обрывается, мысль не закончена». Найдено и починено пять причин; результат замерен ручной разметкой на одном материале три раза.

| замер | чистых | приемлемых | брак |
|---|---|---|---|
| до работ | 3/20 | 3/20 | 85% |
| середина | 9/20 | 13/20 | 35% |
| после | 11/15 | 13/15 | **13%** |

Что чинилось:

1. **Дрейф конца.** `_prefer_longer_end` тянул конец до заполнения длительности — до +27 с за смысловую границу. Удалён. Снап конца теперь punctuation-first: первое слово с `.?!` после `r0_end`, окно `max_end_search_sec`, фолбэк на паузу.
2. **Обрезка длинных моментов с не той стороны.** Резался конец (где развязка), теперь режется начало. Конец назад двигается только если подрезкой начала не уложиться.
3. **Потолок длительности.** 59 → 90 с. Площадки допускают до 180 с, но вовлечённость падает раньше.
4. **Отсутствие пунктуации в транскрипции.** `initial_prompt` для Whisper поднял плотность знаков с 1.8 до 9.2+ на 100 слов. Промпт подаётся в каждый чанк.
5. **Утечка промпта в транскрипт.** Затравка попадала в вывод как услышанная речь. Промпт переписан как непродолжаемый + постфильтр совпадений.

Плюс: детерминированный `dangling_start` с ремонтом (сдвиг начала к границе предложения вместо отбрасывания), дедуп по перекрытию диапазонов, интервью-режим (`source_kind`) — границы по смене говорящего через тире и вопрос ведущего как вход клипа, обрезка висячих слов на хвосте.

**Ключевой методический вывод:** метрика качества считается сама — модель на этапе R0 сообщает `r0_start`/`r0_end`, и отклонение финальных границ от них есть мера брака. Ручная разметка нужна только для калибровки, не для мониторинга.

## Текущее ограничение: бесплатный тариф Groq

Несущий лимит — **OTPM (выход) = 1000 ток/мин**, не входной TPM 8000. Он не публикуется в документации и не виден в заголовках; найден прямым пробником (`scripts/probe_groq.py`).

Следствие: `max_tokens=900` ≈ 3 момента на ответ. Урожай определяется **числом запросов**, а не размером чанка — поэтому чанки надо держать мелкими (`r0_chunk_tokens` ~1200), а не крупными.

- **Prompt caching** — не применим (Groq поддерживает только на GPT-OSS, и снимает вход, а упираемся в выход).
- **Обрезка системного промпта** — ~300-400 токенов входа, эффекта почти нет.
- **Платный Developer-тир** — снимает OTPM целиком, ~$0.17–0.55/мес при текущем объёме. **Запланирован к покупке; до тех пор работаем на бесплатном.**

## M2 — Приём по ссылке + стык с экосистемой

1. **Слой приёма (`ingest.py`)** — взаимозаменяемые доставщики (yt-dlp / HTTP / Tailscale / Syncthing / ручное копирование), каждый кладёт файл в `inputs/`. Ядро читает локальный путь и от доставщика не зависит. Привязка по `source` = имя + sha256. Загрузка с Я.Диска уже есть (httpx streaming + Range-resume).
2. **Перенос между машинами** — Tailscale либо Syncthing. Зафиксировать выбор.
3. **Контракт с SMM-постером** — манифест (`title`/`description`/хэштеги + mp4) → формат кросс-постера.

**Выход M2:** вставил ссылку → клипы ушли в SMM-инструмент. Петля экосистемы замкнута.
